# 既存fileの局所修正を完全diffで示す

## 使用条件

既存fileの何を残し、変え、削るかへ合意するために、変更内容の全体を読みやすい一つのunified diffで示せる時に使う。file全文ではなく、全変更行と変更位置を判断できるcontextを合意対象にする。

次の条件を満たす時に選ぶ。

- 変更が一つ、または一続きで読める少数の局所範囲に閉じている。
- 追加行と削除行をすべて含めても、diffとして無理なく通読できる。
- 変更しないfile残部を再掲しなくても、変更後の意味と既存内容への影響を判断できる。

新規fileには使わない。新規documentは`document-heading-outline.md`でoutlineへ合意してから実fileを作成し、そのfileをreviewする。

大規模な変更、離れた多数の変更、複数fileにまたがる変更、file移動等で、完全diffだけでは変更対象と対応関係を判断しにくい場合は`file-change-set.md`を使う。一つのdecisionとして不可分な変更だけを同じ変更集合へ置き、独立して採否を変えられる変更はdecisionを分ける。

## template

````markdown
`{path/to/existing-file}`の{変更範囲}を変更する。diff外の{変更しない範囲}は変更しない。

```diff
 {変更位置を特定できる変更前context}
-{削除する既存内容}
+{追加する内容}
 {変更位置と接続先を確認できる変更後context}
```

{diffだけでは判断できない境界、変更しない範囲、変更後の意味があれば書く。}
````

変更対象に含まれる追加行と削除行を省略しない。変更hunkの途中へ`...`等の省略記号を置かない。contextはfile全文を再掲するためではなく、変更位置、保持される既存内容、変更後の接続先を特定できるだけ含める。

実際のgit patchを適用することが判断対象でなければ、`diff --git`やindex行等のmetadataは必須にしない。合意対象となる内容差分が正確に読めることを優先する。

## ユースケース

- 既存READMEの一つのsectionを置換し、その前後の見出しは維持する。
- 一つの設定blockで、削除する値と追加する値をすべて示す。
- 一つの関数本体を修正し、signatureと隣接する処理をcontextとして残す。
