## イテレーション0: 現在結果から内容・根拠・未完の条件を辿れるようにする

<a id="iteration-0-record-1"></a>

### 判断: 合意と実適用を分けた現在表示は既決の待機条件を保てるか

#### 必要条件・根拠・方法

論点7・11〜13、論点12の既存契約調査を根拠に、導出・委任の現在結果とstatusを具体化する。
利用者decisionの決定表示を流用せず、根拠、現在内容、報告した版、反映先・実結果・未完理由を同じ論点から読める必要がある。
常設summaryや独立flagを作らず、既存の現在結果の原文取得を新しい内容へ接続する。
表記の違いで意味が変わらない箇所は局所的に選ぶが、新しい承認条件・待機期間は追加しない。
未報告、報告後の無応答、応答後の権限不足、部分反映、中断復帰、反映・検証完了を机上照合する。
各状態を記録から判別でき、同じ変更を二重適用せず、完了を先取りしないかを確かめる。

#### 結果

利用者の採否と、AIが根拠付きで行った変更判断とを同じ「決定」で表示するのは、論点12に反する。
また、報告後も未反映である期間を現在結果から判別できなければ、論点13の待機条件を引き継げない。
そこで「現在の変更」を置き、内容と根拠、報告したiteration、反映先と実績、未完理由を一緒に保持する。
現在結果の見出しとstatusの語は、意味を変えない局所的な表現として選んだ。
新しい承認条件や別の台帳を追加する判断ではない。

| 照合case | 現在結果での区別 |
| --- | --- |
| 保存直後 | 未報告、対象成果物は未反映 |
| 報告後に無応答 | 報告したiterationと次の問いを記録し、未反映を維持 |
| 応答後も権限不足 | 応答の所在と未反映の理由を分けて記録 |
| 一部だけ適用 | 適用済みの対象と残件を区別し、全体は未完 |
| 中断から復帰 | 現物と記録を再照合し、適用済み部分へ重ねて適用しない |
| 適用・検証完了 | 明記した対象についてのみ反映済みとする |

提案内容の形成・訂正中は「調査中」、内容が成立して適用を待つ間は「反映待ち」、
対象への適用と検証後は「反映済み」とする形にした。
未報告・応答待ち・権限不足をstatusの組合せへ増殖させず、現在結果中の事実で区別する。
親の未完判定には反映待ちも含め、利用者decisionの決定とAI変更の反映済みを別々の終端として扱う。

通常readerは、この現在結果と最新の未完iterationを原文取得する。
分割後の索引へ状態を複写せず、引き継ぎ時の全履歴読取も省略しない。
helperの出力field・実装・実行testは未実施であり、机上での契約照合に限る。

#### 次の処理

論点14へ変更内容0と記入例を保存し、論点15と併せて次の利用者判断前に報告する。
design.mdへの同期は、その作業への次の応答後に行う。
この設計記録自体は、新statusの本体適用前なので既存の「応答待ち」に未反映の説明を添える。

### 検証: 報告済み変更をdesignへ同期して現在結果を閉じる

#### claim・合格条件・方法

論点16の提案0への実際の応答「b」が届き、論点14・15への訂正は含まれていない。
これは論点13が定めた次の作業応答であり、論点14の新たな採否を表すものではない。
変更内容0をdesign.mdの現在結果・status・親の完了判定・readerへ同期し、保存した契約との対応を机上照合する。
未報告、報告後の無応答、応答後の適用条件不足、部分反映、中断復帰、反映・検証完了を区別できれば合格とする。
実装・配布は対象にせず、同期後に現在結果へ対象と実績、応答の所在を残す。

discussionの図はfacilitate-discussionのraw text規約に合わせ、未完の変更内容0の描画だけをtextへ揃える。
遷移・条件は変えず、論点11〜13の完了済み履歴も変えない。

#### 結果

変更内容0をdesign.mdへ同期し、六caseを机上照合した。
未報告・報告済みの区別と応答の所在は現在結果へ、適用条件不足・部分適用は残件へ保存できる。
中断復帰では現物との照合を求め、反映済みは対象への反映・検証完了に限る契約になった。
通常readerは現在の変更と最新の未完iterationを原文取得し、helperによる合意認定と索引への状態複写は追加していない。
親の未完判定へAI変更を含め、通常decisionの決定とは別の終端として扱える。

文字列照合で現在結果・報告した版・部分適用・中断復帰・親判定・readerの保存を確認した。
変更前snapshotとの照合で、論点11〜13の完了済み部分とplugin成果物が不変であることも確認した。
最初のsnapshot取得は出力打切りで失敗し、書込み前にdigestへ絞って取得し直した。失敗した出力を取得済み扱いにはしていない。
diagramは未完の提示の描画だけをraw textへ揃え、遷移・条件は維持した。
設計への同期は完了したが、helper・template・plugin本体の実装や実行testは未実施である。
