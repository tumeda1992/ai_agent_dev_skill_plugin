# 内部検討記録: 論点7 — 分割後の読取範囲

**discussion:** [task-design-discussion.md](../task-design-discussion/task-design-discussion-6-10.md)

**論点:** 論点7

## 開始context

10論点を超えた議論を5論点単位で分割し、所在だけの索引を同じdirectoryへ置く。
状態・親・現在の決定・未決提案は範囲本文が正本であり、索引へ転記しない。
今回決めるのは、通常進行でAIへ取り込む範囲と、設計引き継ぎで全履歴を読む契約との関係である。
抽出を実装するfile、command、出力schema、全体構造の検査手順、移行と中断復帰の実装は別途設計する。

<a id="iteration-0"></a>

## イテレーション0: 現在結果の横断読取と担当fileの履歴を組み合わせる

現行facilitate-discussionはdiscussion全文と対象の内部log全文を読み、他論点の根拠を使う時は当該logも読む。
設計引き継ぎは独立再構成後に全decisionと過程を照合し、canonical file digestを再確認する。
分割を理由にこの引き継ぎを通常進行の軽い読取へ置き換えることはしない。

<a id="iteration-0-record-1"></a>

### 検証: 別範囲の制約と訂正を見落とさず、無関係な旧履歴を毎回読まずに済むか

#### claim・合格条件・方法

既存のfacilitate-discussionの読取・書込直前再読込規則とtask-design-work-handoff-contracts.mdを照合し、
通常は全論点の現在結果を原文抽出して読み、対象と根拠に使う範囲本文・内部logは全文読む案を机上検証する。
全体の現在結果にはmetadataだけでなく、現在有効な決定、未決論点の最新の提示と背景・応答、仮決定・停止条件を含める。
本文の要約を新たな正本として保存する案ではなく、現在のfileから必要なblockを取得する案とする。

合格条件は、別fileにある決定・未決事項・親子の変化を見落とさず、
対象論点の過去iterationを読めること、通常進行で無関係な全過去iterationを一律読取しないこと、
別ownerへの設計引き継ぎの独立再構成・全decision coverage・digest契約を緩めないことである。
過去論点の再開、別範囲の後続決定、親子が別fileにあるcase、抽出不能・出力打切り、
引き継ぎ前後、読取後のfile変更を当てはめる。これは契約案の机上照合であり、抽出実装の動作試験ではない。

#### 現行契約との対応

facilitate-discussion/SKILL.mdの「必要な読取」は、対象logを全文読み、
他論点の根拠を使う時は現在decisionと当該logへ広げて、後続訂正を辿る契約である。
分割後もこの根拠確認は維持する。変更するのは、無関係な全過去iterationを毎回AIへ読ませる範囲である。
書込対象fileの全文再読込も維持し、分割済みの場合の対象は実際に更新する範囲本文または索引とする。

task-design-work-handoff-contracts.mdは、独立再構成の後に全decisionと主要な棄却案の理由を照合し、
比較時と完了直前のcanonical file digestを一致させることを要求する。
従って引き継ぎは通常の軽い現在結果の読取だけで代替せず、全範囲本文を通読する。
digestの対象も索引だけへ縮めず、全範囲本文と根拠に読んだ内部logを含める。
bounded extractorから受け取れる元の依頼内容と上位制約の境界は変更しない。

#### case照合と案の具体化

| 机上case | 必要な読取と照合結果 |
| --- | --- |
| 全30論点から論点3を再開 | 全論点の現在結果を確認し、1〜5の本文と論点3のlogを全文読む。最大範囲を再開先と誤認しない |
| 論点18の決定が論点3を制約 | 現在決定の原文を全論点から読むため制約を把握できる。根拠に使う16〜20の本文と論点18のlogへ広げる |
| 親1と子23が別file | 全体のmetadataで関係と未決状態を把握し、親を更新する時は1〜5も全文再読込する |
| 未決の最新提案に訂正feedbackがある | statusだけで判断せず、最新の提示・背景・応答を原文で読み、訂正を取りこぼさない |
| 抽出結果が長く出力が途中で切れる | 未取得を把握済みとしない。分割取得し、不足が残れば進めない |
| 旧形式で抽出blockを判別できない | 当該fileの原文全文へ読取を広げる。正本や構造を一意に判定できなければ停止 |
| 読取後に別範囲が変更される | 書込前に読取集合の更新を確認し、変化があれば現在結果を再取得して影響を再評価する |
| 別ownerが設計を引き継ぐ | 独立再構成後に索引・全範囲本文を読み、全decision coverageとdigestの照合を行う |

metadataだけの横断抽出では、論点18に何が決まったかを読めず、対象に明示linkがなければ制約を落とす。
その反例から、全論点の現在決定の本文も原文で取得する案にした。
未決論点では最新iterationの提示・背景・応答を読み、現在の仮決定・停止条件も取得する。
記録全体の前提となる論点外の本文も読取対象にする。

抽出するのは原文blockであり、要約を生成して代替したり、常設のcurrent-state fileを増やしたりしない。
出典fileと論点・回・見出しを付け、原文へ戻れる形で取得する。
範囲本文を機械が走査する量と、AIへ渡す過去履歴の量を分けることにより、
現在の制約と未決事項は保ちつつ、無関係な旧案・feedbackの毎回通読を避けられる。

#### 保証できる範囲と未検証

通常進行で全体の現在結果と対象履歴を読むこと、引き継ぎでは全履歴を読むことは、
既存の正本性・根拠確認・引き継ぎの要求と両立する契約案として成立する。
現在結果自体が大きければ読取量は増え、一定token数に必ず収まる保証はしない。
抽出parser、全体構造検査、snapshotの照合方法、file単位の取得commandは未実装・未検証であり、次に具体化する。
この段階で現行skillの読取を既に省略できるようになったとは扱わない。
