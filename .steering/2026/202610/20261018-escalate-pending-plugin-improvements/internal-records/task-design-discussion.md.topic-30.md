# 内部検討記録: 論点30 — 正式修正による暫定指示の終了判断

**discussion:** [task-design-discussion.md](../task-design-discussion/task-design-discussion-26-30.md)

**論点:** 論点30

## 開始context

元作業はまだ進行中で、作業完了による終了には至っていない。
暫定指示は元作業内だけに効き、maintenance-plugin-contextが管理する。
実行version変更時には適用を止めて継続を毎回確認し、終了したfileは理由・根拠とともに残す。
正式修正への取込み後の終了判断は別に残されている。
終了時期が明示されていない指示について、実際に使う正式版が指示の役目を満たした場合の判断権限を比較する。
明示された終了条件の実行は対象外である。

## イテレーション0: 正式版で代替できることの確認と、終了を決める権限

<a id="iteration-0-record-1"></a>

### 判断: 正式修正が指示を不要にした時の既定動作

#### 判断対象・必須条件・根拠

maintenance-plugin-contextが実行中の正式版と元指示を照合し、その役目を全て満たすと確認できたら終了して報告するaと、照合結果と終了案を利用者へ示して回答を待つbを比較する。
引き渡し・merge・releaseだけで終了せず、実際にその作業で使う契約と、複数consumerを含む元指示の範囲を確認することを必須とする。
一部だけの修正、同名の機能、確認不能を完全な代替と扱わず、version変更後の指示を勝手に継続しない。
根拠は論点21の引き渡しと改善完了の分離、論点26の継続確認、論点27のfile保持、論点29の作業完了との区別である。
比較軸は、確認済みの不要な指示を残さず切り替える負担の小ささと、意図の充足・終了の最終判断を利用者が持つことである。
引き渡しのみ、release済みだが未使用、使用版で完全代替、一部代替、照合不能、明示された終了条件の六caseを机上比較する。
consumer接続・状態名・記録項目の詳細や、別作業の指示の追跡は含めない。

#### 比較結果と推奨

bの、照合結果を示して利用者の終了確認を待つ案を推す。
論点26で利用者は、無関係なversion更新でも指示の継続を自分で判断するaを採った。
正式修正が元の意図を満たしたかについても、AIが根拠を示し、終了の最終判断は利用者に残す方がその運用と揃う。
ただし論点26は終了判断を別に残しているので、bだけが合意から一意に決まるとは扱わない。

| case | AIが終了して報告するa | 利用者の終了確認を待つb |
| --- | --- | --- |
| plugin側への引き渡しのみ | 終了させない | 同左 |
| 修正版release済みだが作業では旧版を使用 | 終了させない | 同左 |
| 実際に使う正式版が元指示の全範囲を代替 | 根拠を記録して終了・報告し正式版へ切替 | 根拠と終了案を示し回答後に終了・切替 |
| 一部consumerや一部の振る舞いだけ修正 | 指示全体を終了させない | 同左 |
| 旧指示の意図や使用版を照合できない | 推測で終了させない | 同左 |
| 利用者が終了条件を明示済み | 指示された条件と権限に従う | 同左 |

aは、正式版が全ての役目を引き受けたことを確認した時点で、重複する例外を待たせず除ける。
合意すれば、この限られた終了判断を管理担当へ任せる意味になる。
ただし同名機能やrelease noteだけで済ませず、元指示の対象・動作・条件と新しい契約の対応をAIが確認する必要がある。
これは指示を新versionで自動継続する許可ではなく、役目を満たした指示を終了し、正式版へ切り替える権限の追加である。

bも同じ照合を行うため、利用者へ丸投げする案ではない。
違いと根拠を示して、版更新時の「継続するか」という確認の場で、終了する案も一緒に判断できるようにする。
既に同じ終了を明示承認した場合に再確認はせず、回答前は終了扱いにも指示無視の通常動作にも切り替えない。
version更新で停止している暫定動作は、論点26どおり未承認で継続せず、影響しない作業は進められる。
終了判断のため回答待ちが残り、利用者が返さなければ影響する切替は進められない点が代償である。

完全な代替を確認する基準は両案で共通であり、誰が終了を確定できるかだけを採否対象にする。
一部だけ改善された指示を自動で分割・改訂して残すこと、指示の意味を正式版へ合わせて書き換えることは今回許可しない。
明示された条件の実行や記録済みの作業完了による終了は既存の指示・論点29に従い、今回のbで改めて確認待ちへ変えない。
終了後のfileは論点27どおり残す。
これは六caseの机上比較と既存decisionの照合であり、修正版への実切替や指示の状態更新を実行した結果ではない。

### 検証: 正式修正の確認と、終了の承認を区別して選べるか

#### claim・合格条件・方法

提案保存後、document-reviewで同じ正式修正の例から、両案の確認内容は同じで、終了の確定権限と回答待ちが違うことを判断できるか確認する。
引き渡し・releaseだけ、一部修正、照合不能は終了対象から外し、version変更時の未承認継続や指示無視への切替を認めない。
明示済みの終了条件と作業完了による終了を再確認待ちへ変えず、file保持と一作業限定を維持する。
Nodeで構造・link・範囲・索引・内部記録を検査し、開始snapshotからの履歴保持、論点29の実応答の一回保存、論点30の空feedback、未合意の終了判断をdesignへ反映していないこととplugin本体の不変を確認する。

#### 結果

document-reviewの作成・更新観点で、正式版への取込みを確認する作業と、終了を確定する権限を分けて比較できることを確認した。
元指示と正式版の対応を両案ともAIが確認するため、bは照合を利用者へ丸投げしていない。
aは確認後の終了・切替まで任せる案、bは根拠を見た回答を待つ案であり、質問回数だけの違いにはしていない。
引き渡し・releaseのみ、一部代替、照合不能を終了の根拠から外し、未承認の旧指示継続も、回答前の指示無視への切替も認めていない。
明示された条件と作業完了による終了には再確認を追加せず、file保持と一作業限定を維持した。
具体例・条件・代償を本文から読め、既存の履歴を削らず、新たな機密情報も記載していない。

Node検査は39文書、相対link 102件、30論点、6範囲fileで問題なしだった。
親論点1は子論点待ち、論点29は決定、論点30は応答待ちで、提案0のfeedbackは空である。
開始snapshotの本文は論点29のstatus変更以外を保持して追記し、論点29の内部記録も保持した。
実応答「a」は論点29へ一度だけ保存されている。
今回の変更はdesign、索引、26〜30の本文、論点29の内部記録の更新と、論点30の内部記録の追加である。
designには論点29の合意だけを反映し、正式修正後の終了判断は未決として残した。
file削除、plugin本体の変更、実運用のtemporary-overrides作成や指示終了は行っていない。
これは文書検査と机上reviewであり、正式版への切替や状態更新の動作確認ではない。

### 検証: aの終了判断を合意として反映し、自動継続と区別する

#### claim・合格条件・方法

実応答「a」を提案0のfeedbackへ一度保存し、新iterationを作らず論点30を決定する。
正式版が元指示の全範囲を代替したと確認した場合に管理担当が終了・切替して報告することと、指示を継続する場合のversion更新ごとの確認を、現在決定とdesignで区別する。
先行論点26の現在決定には論点30への接続だけを追記し、過去の提案・応答は保持する。
未採用の追加終了承認をdesignへ混ぜず、正式修正による終了を未決とする現在記述だけを整える。
Nodeで構造・link・開始snapshotとの履歴保持・変更対象・実応答の一回保存とplugin本体の不変を検査し、document-reviewの作成・更新観点で採否の範囲を照合する。

#### 結果

実応答「a」を一度保存し、新iterationなしで論点30を決定した。
document-reviewの作成・更新観点で、全範囲の代替を確認した管理担当が終了・切替して報告する契約をdesignへ反映し、未採用の追加終了承認を混入させていないことを確認した。
指示を継続する場合の毎回確認は残し、論点26の現在決定へ論点30との接続だけを追記した。
引き渡し・releaseのみ、一部修正、照合不能での終了、自動改訂や旧指示の自動継続は許可していない。
正式修正後の終了を未決とするdesignの現在記述を整え、取下げ・記録項目・接続の詳細は未決として残した。

Node検査は39文書、相対link 102件、30論点、6範囲fileで問題なしだった。
開始snapshotの本文は論点30のstatus変更と論点26の現在決定への一文追加以外を保持して追記し、既存の内部記録も保持した。
実応答「a」は論点30へ一度だけ保存された。
変更した既存fileはdesign、26〜30の本文、論点30の内部記録だけで、追加・削除はなかった。
plugin本体は不変で、実運用のtemporary-overridesの作成や実指示の終了・切替は行っていない。
これは文書検査と机上reviewであり、正式版への切替機構の実行結果ではない。
