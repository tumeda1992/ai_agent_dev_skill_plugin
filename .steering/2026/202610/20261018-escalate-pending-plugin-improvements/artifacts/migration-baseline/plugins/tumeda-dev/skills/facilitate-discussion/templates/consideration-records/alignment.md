# 認識合わせを必要とする背景

## 共有事実と未共有の前提

自力で確認した事実と、そこから自分が読んだ意味を分ける。何が不足していて、なぜ外部sourceでは確定できないのかを示す。
本formatは内部logに置く検討であり、discussion側の判断背景、外向き質問本文、受領した回答欄の代わりではない。調べられる事実を質問へ逃がさず、必要なuser-owned inputだけを残す。

## 問う対象と、回答で変わる判断

回答・訂正してもらう前提や見方を具体化し、それが分かるとどの判断が進むかを結ぶ。答えを推論で補わず、未提示案への採否を混ぜない。
判断可能な定義・見方の採用ならproposalであり、「認識合わせ」という語だけでこの形式へ分類しない。

## 背景の記入形と例

実施前には共有事実、現在の読解、必要inputと確認方法を保存する。本人が答えるまで結果を確定しない。

```markdown
##### 認識合わせ: 利用者が「再送」に期待する対象

###### 共有できる事実と、現在の読解

仕様には失敗した通知を再送できるとある。初回の配送内容を繰り返す意味にも、最新設定でもう一度届ける意味にも読める。既存記録だけでは利用者の期待を特定できない。

###### 本人にしか確定できない前提

宛先を変更した直後、過去通知の再送でも新しい宛先へ届けたいか。この経験と優先順位を聞く必要がある。回答によってsnapshot固定と再解決のどちらを要件へ採るかが変わる。
```

外向き本文ではこの対象を具体的な質問にする。受領した原文・結果は同じ回の回答欄に保存し、次の検討記録は必要条件への影響だけを参照する。部分回答なら埋まった範囲と残る空白を分ける。
