# 命名

名前は本質。名前を付けるあらゆる場面で守る標準。

## この群の置き方

二つの軸で分ける。

**軸1: 判断基準か、手段か**

- 判断基準（`core.md`、`file.md`、`method.md`）: どういう名前が良いか
- 手段（`what_to_try.md`、`reverse_translation.md`、`review.md`）: 良い名前へどう辿り着くか、良いかどうかをどう確かめるか

判断の問い: **「この内容は、名前の良し悪しを判定するものか。それとも良い名前へ辿り着くための行動か」**

**軸2: 対象を問わないか、対象種別ごとか（判断基準の中での分け方）**

- `core.md`: 名前を付ける対象が何であっても成立する原則
- 対象種別ごとのfile（`file.md`、`method.md`）: その対象にだけ成立する規則

判断の問い: **「この規則は、名前を付ける対象が何であっても成立するか」**

- 成立する → `core.md`
- 特定の対象種別を前提にしないと成立しない → その種別のfile
- 特定の設計手法を採ったときにだけ存在する概念（entity、集約等）を前提にする → この群の外。その概念を扱う標準へ置く（例: エンティティ固有の命名判断は [entity_modeling/](../entity_modeling/README.md)）

`core.md` は汎用に共通する部分（積集合）だけを扱う。個別の対象種別の規則を足していく（和集合）運用はしない。和集合にすると、読み手が「この規則は自分の場面に当てはまるか」を毎回判定することになり、標準としての適用範囲が濁る。

## 各fileの守備範囲

| file | 扱うもの | 扱わないもの |
| --- | --- | --- |
| [core.md](./core.md) | 名前を付ける対象が何であっても成立する原則 | 特定の対象種別にだけ成立する規則、良い名前へ辿り着くための手段 |
| [file.md](./file.md) | ファイル名に固有の規則 | どの対象にも効く原則（`core.md` を参照） |
| [method.md](./method.md) | メソッド名に固有の規則 | どの対象にも効く原則（`core.md` を参照） |
| [reverse_translation.md](./reverse_translation.md) | 初見の人にどう読まれるかを検算する手段 | 検算の結果をどう書くか（`review.md` を参照）、判断基準そのもの |
| [review.md](./review.md) | レビューの書き方、評価水準の合わせ方、レビュー結果の扱い | 観点の中身（各fileが正本） |
| [what_to_try.md](./what_to_try.md) | 行き詰まった状態から引く索引と、他fileに属さない四つの手段 | 他fileが本体を持つ手段の中身（索引から参照するだけ） |

対象種別のfileを増やすときは、まずその規則が `core.md` へ入らないことを確認する。`core.md` へ入る規則を種別fileへ書くと、他の種別から見えなくなる。
