# 誤書込みによる先行reviewの失効

validation-run-1/result.jsonはfailed。templateへ能力ledgerが混入し、保存済み独立観測の22行/2006bytesから8506行/3452402bytesへ変化した。既存portable guardが移植元名patternと利用者絶対pathの混入を検出した。guardの誤検出として除外しない。

原因はexecutorのledger更新scriptで保存先変数pをnewfilesのloop変数にも使い、最後のtemplate pathへledger出力を書いたことである。予定したcontract ledger本体は更新されず、templateが上書きされた。破損版とledger更新前版をledger-path-repair/へ保存した。

structure-review-after-callers.mdは破損後の対象集合をhashに記録しながらtemplateの実内容を読んで検出せず、合格とした。この結果は現行版の根拠として失効する。document-review-callers.mdも新skillの編集後版についての結論を流用できない。以前の有効な新skill評価・挙動観測を、破損中の実物へ適用してはならない。失効結果は履歴として残し、次の実物全文reviewで置き換える。

復元は、誤書込み出力内のA1行に残った正しいtemplate原文と行番号から元bytesを再構成し、独立観測のSHA-256へ完全一致することを確認した上で実施した。出力ledgerは正しいwork_directoryのcontract ledgerへ保存し、templateは正しい22行本文へ戻した。保存先を役割ごとの不変変数に分け、loop変数を保存先へ使っていない。

新skill5 fileの集合・実解決先・内容を構文修復後の有効な識別と照合し、全件一致した。他の新skill本文・UI metadata・fixtureにはこの誤書込みはない。caller6 fileの実変更は合意済み接続の追加だけで、旧guardは変更していない。正しい保存後に実物全文を再読し、集合・hashの照合だけで構造reviewを代替しない。
