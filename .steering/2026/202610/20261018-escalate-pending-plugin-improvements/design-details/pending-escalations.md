# 改善提案の保留と引き渡し

[全体設計へ戻る](../design.md)

escalate-plugin-skill-fixが、明示的に保留された改善提案を元作業に保存し、指示された条件でplugin側へ渡す。
保留メモは当時の提案の控えであり、今の動作を変える[暫定指示](./temporary-overrides.md)とは別に管理する。

## 保留を成立させる指示

起動後、作業先をplugin repositoryへ切り替える前に明示保留を確認する。
「この改善は後で」と、対象・期間を指定した「この作業中の改善は全部後で」の両方を扱う。
範囲や期間が不明なら、その不足を確認する。plugin内で作業している時も同じ判定を通る。

明示保留がなければ既定の即時escalationへ進む。
慣習、agentが作った方針文書、メモの存在だけでは保留を成立させない。
保留の権限を別作業や暫定動作の変更・実装・公開へ広げない。

## 元作業へ保存する内容

元作業の `pending-escalations/001-<短いkebab-slug>.md` のように、一改善一fileで保存する。
番号は同directoryの最大連番+1を3桁以上で表し、再利用・自動改名・global ID化をしない。
初回のslugは内容からAIが選び、既存fileは上書きしない。元の議論からメモを参照する。

| 節 | 扱い |
| --- | --- |
| 保留時の内容 | 提案、具体例、根拠、指示原文と出典、対象、再開条件を保存し、固定する |
| 関連情報 | 後の訂正・追加証拠の所在と影響を追記する。何もなければ節を省く |
| 追跡 | 保留・引渡し中・引渡し済み、条件の証拠と実応答、受領先と確認、未完理由を更新する |

固定本文を後の議論で直さず、訂正・別提案は元の議論などへ残して関連付ける。
再開時の併読は増えるが、何を後回しにしたかを変質させない。
メモを第二の議論場所にせず、引渡し後の改善設計はplugin側を正本にする。

作業directoryがなければ記録場所を先に定め、特定できなければ元作業の担当へ戻す。
repository共通の置き場、別作業の探索、別の索引・一覧fileは追加しない。

## 条件を確認して再開する

| 利用者の指示 | 再開の条件 |
| --- | --- |
| 「設計が終わったらescalateして」 | 同じ作業の設計完了の証拠を確認して渡す |
| 「終わったらescalateするか聞いて」 | 条件成立後の利用者の回答を待つ |
| 「今は保留」 | 解除指示を待つ |
| 「落ち着いたら」など成立基準が不明 | 意図を確認する |

元の指示で対象・条件が明確なら、同じ採否を聞き直さない。
根拠となる指示と条件成立の証拠、必要な実応答を追跡へ記す。
後の保留継続指示、範囲・必要権限の変化、証拠不足は古い条件だけで押し切らず、元の指示で覆えない箇所を確認する。

再開時は固定本文・関連情報・現物を併読し、現在も妥当な引渡し内容を作る。
過去の誤りを現行事実として送らない。既存の汎用化・repository判定・steering起動を使う。
新たな監視やsession自動起動、改善の実装・公開・commitの権限を追加しない。

## どこまで追跡するか

plugin側が受領し、作業記録へ辿れることを確認して引渡し済みへ更新する。
転送先を作っただけでは完了にしない。失敗時は同じメモへ未完範囲と理由を残す。
再開時は既存の転送先を確認し、同じ作業を二重起動しない。

メモは削除せず残す。修正・release・利用先導入の進捗同期は必須にせず、必要時は引渡し先を読む。
引渡し済みを改善済みとは扱わず、元作業の再開・完了への新たなgateも加えない。
引き渡しだけで暫定指示を作成・終了させない。

## 記入例

以下は架空の例。実物では出典を実際のfile・論点・節へ結ぶ。

```markdown
# 保留メモ: 議論の分割

## 保留時の内容

提案: 10論点を超えた議論を5論点単位へ分ける。
具体例: 現在の論点を探すために長い全履歴を開いていた。
根拠: 原文を保ったまま読取単位を小さくする。
保留指示: 「この作業の設計が終わったらpluginへ渡して」
出典: 元の議論の対応する応答。
対象: この改善提案。条件: 同じ作業の設計完了。

## 追跡

状態: 保留。
条件の完了証拠: 未取得。引渡しは未実施。
```

## 実装するfile

`plugins/tumeda-dev/skills/escalate-plugin-skill-fix/` にpending-escalations.mdとtemplates/pending-escalation.mdを新設する。
SKILL.mdから明示保留がある時だけ内部指示へ進み、保留がなければ現行経路を維持する。
内部指示の見出しは「保留を保存する」「再開条件を確認する」「現在の提案を引き渡す」「受領先を記録する」。
