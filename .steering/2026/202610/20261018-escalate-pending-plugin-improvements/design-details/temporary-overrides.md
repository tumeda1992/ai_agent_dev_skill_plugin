# 作業限定の暫定指示

[全体設計へ戻る](../design.md)

maintenance-plugin-contextが、その作業で各skillへ適用する暫定指示を管理する。
安定したrepositoryの事実と、利用者が指定した動作ルールを分け、取得・選択・競合・版の確認・終了を一箇所で扱う。

## 指示の範囲と保存先

対象は元作業一つ。未完了の同じ作業の再開には使い、別作業へは引き継がない。
別作業でも使いたい時は改めて指示を受ける。repository共通の指示登録は今回作らない。

元作業の `temporary-overrides/001-<短いkebab-slug>.md` に、独立して改訂・終了できる一指示を一fileで保存する。
一発言・一skillで区切らず、複数skillへ効く同じ指示の正本は複製しない。
連番は同directoryの最大値+1、3桁以上、再利用なし。必要時だけ作成し、終了済みも同じfileを残す。

保留メモのpending-escalationsとは隣り合う別の保存先とし、議論には合意の経緯を残す。
安定factの `.agents/skills/tumeda-dev-plugin-context.md` やその配布template、repository共通の場所へ指示を混ぜない。
保留メモの存在・引き渡しは、指示の成立・終了の根拠にしない。

| templateの節 | 保存内容 |
| --- | --- |
| 指示 | 元作業の同定情報、利用者の指示原文と出典、対象skill・処理・条件、現行の動作、明示された終了条件 |
| 適用状況 | 有効・停止・終了、確認した実行pluginのversion・取得元・確認根拠、未解決事項 |
| 変更と終了の履歴 | 変更前後、指示・判断の根拠を追記。古い意味を消して書き換えない |

関連指示が複数fileに分かれても、重なりの確認は省かない。
元作業を特定できなければ担当へ戻し、別作業や共通の場所へ推測保存しない。

## 各skillが受け取る時

各skillは、実際の新規起動、別sessionからの再開、resume、把握した変更時に指示を取得する。
元作業がまだ未確定なら、元作業の担当が確定してから取得する。
通常の返信、think-throughの毎turn適用、内部指示fileの読直しを定期取得の理由にはしない。

呼出し側は、取得・登録・更新・終了の目的、元作業のexactな場所、対象skill・処理、実行pluginの取得元を自然言語の依頼へ添える。
管理担当は不足を呼出し側へ返し、別作業を探索しない。
安定factと暫定指示の依頼・返却は別々に扱い、fact依頼がなければ空のinstanceを作成・更新しない。

| 取得結果 | 意味 |
| --- | --- |
| active | 対象・条件・版を確認した指示を渡す |
| none | 元作業を確認し、該当する有効指示がない |
| paused | version更新・競合等で適用を止め、判断を返す |
| unavailable | 所在・読取・実行版等を確認できない |
| ended | 終了を記録・通知した。実効指示には含めない |

返却には状態に加え、指示のpathと改訂、対象・条件、実効指示、実行版の根拠、停止・終了理由を示す。
取得だけで合意・有効性を認定せず、取得不能をnoneへ変換しない。

同じsessionで登録・更新・終了した場合、管理担当が現在の対象skillへ更新後の内容を返す。
進行中にすぐ反映したい変更は会話で変更・読直しの必要を伝える。
通知されていない編集の即時発見や、未更新の旧版skillによる自動取得は保証しない。
background監視・別作業の探索は追加しない。

## 競合と実行versionの変更

同じ対象に効く全指示を読み、上位指示、安全・権限上の制約、確認済みのrepository factを上書きしない。
利用者が置換・取下げを明示していれば、その範囲で更新・終了する。
なお並立不能な指示が残れば、矛盾箇所と影響を示して対象の暫定動作を止め、解決を求める。
fileの新しさで優先したり、意味の一部を切り取って合成したりしない。

実行versionは、実際に使うSKILL.mdの取得元と同じ配布単位の宣言で確認する。
repositoryの最新版とcacheを混同せず、上流のreleaseや保留メモの引渡しだけで実行版が変わったとは扱わない。

実行versionが変わったら、適用をいったん停止する。
管理担当が実際の変更を確認し、指示を継続してよいか利用者へ毎回尋ねる。
対象規則が不変でも自動継続しない。無関係な更新でも確認は増えるが、版をまたぐ判断を利用者が持つ。
版の確認不能や対象の変更は根拠と影響を示して必要な判断へ戻す。更新による停止を終了と混同しない。

止めるのは影響する暫定動作だけで、指示を無視した通常動作へ黙って切り替えない。
無関係な作業やfact取得まで止めない。

## 終了しても記録を残す

明示された期限・終了条件に従う。終了時期が別途指定されていない場合は、元作業の完了や正式版による全面代替で終了する。
利用者の明示取下げも、その範囲で終了の根拠とする。

元作業の完了は既存の担当が判断・記録し、管理担当へ通知する。
一返信・一skill呼出し・sessionの終了、中断、承認待ちは元作業の完了ではない。
管理担当による独自の完了判断や新しい完了承認gateは作らない。

実際に使う正式版が指示全範囲の役目を満たしたと確認できれば、根拠を記録して終了し、切替を報告する。
同じ終了への追加承認は求めないが、対象・動作・条件と、複数skillへ効く全範囲を照合する。
merge・release済み、同名機能、一部修正、照合不能では全面代替と認定しない。
残る差は必要な判断へ戻し、一部だけ残す自動分割・改訂や意味の書換えは行わない。
全面代替による終了は、版更新時の自動継続を許す規則ではない。

終了状態・理由・根拠を同じfileへ残し、本文を適用候補から外す。
指示を消さず、作業を後日再開しても自動復活させない。必要なら新たな指示を受ける。

## 適用例

架空例として「この作業では議論の分割を暫定適用して」と受けた場合、
原文・出典・元作業・実行元を記し、対象をfacilitate-discussionの保存処理、状態を有効、確認版を8.0.2として保存する。
8.0.2は例の値であり固定defaultではない。

8.0.3へ変わったら、対象外の修正だけでも停止して継続を確認する。
ただし実行中の正式版が指示全範囲を代替したと確認できれば、終了根拠を残して切替を報告する。
一部だけの代替なら勝手に指示を短縮せず、残る差を示す。

## 実装するfileと接続

`plugins/tumeda-dev/skills/maintenance-plugin-context/` にtemporary-overrides.mdとtemplates/temporary-override.mdを加える。
SKILL.mdは安定factと暫定指示の依頼を独立して受け付け、指示処理時だけ内部指示を読む。
内部指示の見出しは次とする。

- 元作業と依頼を確認する
- 記録を登録・改訂する
- 適用候補と実行版を照合する
- 実効指示または停止理由を返す
- 終了を記録する

現存する全 `plugins/tumeda-dev/skills/*/SKILL.md` と新設skill-update-reviewの入口へ、取得時点と作業・対象の受渡しを追加する。
詳細判断は各skillへ複製しない。maintenance-plugin-context自身は内部処理へ進み、自己呼出しを避ける。
steeringと単独の作業担当は、既存の元作業完了を記録した時に終了通知を送る。
