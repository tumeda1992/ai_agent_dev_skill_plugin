# 設計と適用の検討・検証

## 実施前の判断と確認方法

利用者の改善を、既存のexhaustive-review・内部指示・個票・versionへどう結ぶかを調べる。
対象固定とモデル・監督、個別の採否と適用、障害・再開の契約を保持し、変更するのはテーマの扱いと、個票・集合の再検討と終了判断である。
公開先には利用先の固有情報を移さず、指示の一般化で意味を落とさないか、sourceと削除・追加の各行を照合する。

## 設計時のskill-update-review

exhaustive-reviewの全本文と既存のtemplatesを読み、追加する個票・集合の再検討には、探索とは別の入力（既存指摘集合）、判断（修正後にも反例が残るか）、結果（再探索又は終了）と改訂理由があると判じた。
内部指示review-findings.mdへ分け、各走査後に全文を読む入口と、coverageを更新して探索又は終了へ戻す返りを持たせる。単独の外部callerの要求は無いため別skillにしない。
既存の対象固定・適用・障害処理の責務は移さない。設計の変更集合から旧contractのownerが減らないことを差分で確認する。

## skill-creatorの適用元

実行環境にskill-creatorが同梱されていなかったため、OpenAI公式公開sourceの[skill-creator](https://github.com/openai/skills/blob/main/skills/.system/skill-creator/SKILL.md)を取得して全文を読み、既存skill更新の手順を適用した。既存skillのためinitは省略する。
再利用する詳細は内部指示へ置き、入口で必須読取の条件を示す。新しい不要なREADME・インストール説明・UIメタデータは追加しない。quick_validateは公式sourceのscriptを読み、対象のfrontmatter検査に使う。

## 文書reviewとdoc-enricherの方針

初見の担当がどこで再探索・終了・未完へ返すか、具体の反例と対照から判じられるかを確認する。
利用先から移す恒久的な知識は今回のskillと内部指示へ収めるため、別READMEへの重複提案は行わない。実測と机上の判断、未実施を混ぜない。

## 具体例を指示へ当てた結果

| 入力・途中の結果 | 指示から導かれる次の行いと、誤った終わり方との違い |
| --- | --- |
| 挙動維持のみで認可漏れを探す | 正常な利用体験と業務仕様を維持し、不正操作の拒否を根拠付きで指摘する。新UIの提案を既定の目的にしない |
| 設計の穴を探す。正常操作の現行設計にも原因がある | themesを挙動維持へ狭めず、設計変更と影響を個票へ書く。レビューの許可から実装を自動開始しない |
| 複数テーマの片方は正常操作の維持、他方は同じ操作を変えることが必要 | 衝突する操作と優先順位・許可範囲を問う。一方を勝手に外して両方達成としない |
| 初回は0件だが、再開後の対象IDの読取りを未確認 | 0件でも集合の再検討へ進み、その境界を探索する。0件を問題なしの証拠にしない |
| 二重送信の防止指摘だけ揃い、外部成功・手元保存失敗後の再開で二重実行 | 全件修正後の仮定を当てると残る反例なので、結果不明の照合の責任と検証へ戻る。既存個票を磨くか独立原因を加える |
| 重要な仕様を取得できず成立の根拠が無い | 調査先と未確認を残して未完。確定欠陥を創作せず、テーマの指摘が出揃ったとも返さない |
| 重要な境界は全て既存手順又は指摘の責任と検証へ帰着し、変数の好みの名前だけ残る | 追加候補を水増しせず停止の根拠をcoverageへ残す。小さくてもテーマを壊す差は除外しない |

これは指示文を具体の入力へ当てた机上の検証であり、改稿後の自律review・実装・実運用の成功ではない。

## 編集後のskill-update-reviewと文書review

SKILL.md・review-findings.md・finding templateの実物を読み戻した。集合再検討は内部指示へ分離され、入口が各走査後に必須の読取を持つ。新たな外部callerや別の状態正本は無く、追加の切出し候補は無かった。
文書reviewでは、入力・契約・呼出しの境界を示した後で再探索と終了を判断でき、反例・0件・未確認・些末の各枝を読み分けられることを確認した。
元の本文から削ったのは目的・終了・coverageの3文で、保持・拡張した意味をledgerへ対応付けた。工程を増やすことだけを目的にせず、終了の判断を内部指示へ集中した。

## 実行した補助検査

`node scripts/verification/validate-plugin.mjs`は`plugin validation passed`。
OpenAI公式skill-creatorの`quick_validate.py`は`Skill is valid!`。前者は既存のplugin構造・配布値、後者はfrontmatter等の検査であり、テーマの十分性の証明ではない。
versionは四宣言とexpectedReleaseを9.1.0へ揃えた。原文からの削除・追加の監査と、固有情報の検査をcommit前に行う。
