# 保存する契約と今回の差

[baseline](baseline.json)から既存のexhaustive-reviewへ追加する。利用先のコードや記録は移さない。

## 構造の対応

| 旧構造 | 新しいowner・配置 | 分類 |
| --- | --- | --- |
| 目的とモデル・監督 | 同じSKILL.mdの同節。Solの監督と高推論reviewを保持 | KEEP |
| 入力 | 同節へ任意のthemesを追加。scope/applyと区別 | ADD |
| 出力先・対象固定 | 同じ節、完全SHA/hashと作業treeの区別を保持 | KEEP |
| レビューの走査・指摘作成 | 同じ節と個票。推測で断定しない契約を保持 | KEEP |
| 一巡後の終了 | 同節からreview-findings.mdの再検討へ渡し、不足なら探索へ戻る | CHANGE |
| 個票・集合の妥当性、全件修正後の反例、些末と未確認の停止 | review-findings.mdの4節。担当は同じreviewer、結果はcoverage | ADD |
| README/coverageの役割 | 同じ節。coverageへ集合の再検討と停止根拠を加える | ADD |
| 合意と適用 | 同じ節。正常な利用体験を守る意味、既存承認、1指摘1コミット、pushを保持 | KEEP |
| 実行中の障害と返却 | 同じ節。60秒deadline、再開と未完の区別を保持 | KEEP |
| finding template | 既存の全field・必須節を保持し、テーマとの関係と対照を追加 | ADD |

## 変える意味と根拠

1. 目的は指摘を保存するだけでなく、指摘集合を直してテーマへ届くかを再検討する。利用者の明示指示に基づくCHANGE。
2. 終了は範囲と主要観点の走査だけでなく、集合に残る重要な反例と未確認から判じる。元の範囲確認と未確認の保存は維持するCHANGE。
3. coverageは範囲・除外・未確認・机上/実測を保持し、テーマの例・再検討・停止根拠を加えるADD。
4. themesの任意入力、テーマと修正許可の区別、個票の責任・依存・検証例は、同じ上位の指示に必要なADD。両立不能なテーマは確認し、片方を捨てて完了にしない。

SKILL.mdの削除行は上の三つの文だけで、他の非空行は原文のまま新本文に存在する。findingの旧非空行は全て保持する。追加行はテーマの入口、集合再検討の読取、報告、個票の対応に分類し、別の採否・モデル変更・アプリ変更へ広げていない。
新しい内部指示は、個票の根拠確認／全件修正の仮定／再探索／終了の四つの判断を実例と反例から説明する。既存ownerの責務を別skillへ二重移管しない。

## 固有情報の適応

利用先の企画名、repository名、絶対path、指摘ID、commitや試行本文は持ち込まない。一般的な結果不明後の再実行を構成例とし、局所修正だけでは目的を満たさない因果を保つ。元の製品の修正や許諾・運用の採否は移植対象ではない。

## 集計

構造の対応は10単位（KEEP 5、ADD 4、CHANGE 1）。各行の意味と本文の具体の帰着を通読した。
未監査0／未分類削除0／未分類追加0。件数と原文保持の機械確認は意味の通読の代替ではない。
