# CR-001　一括受注できない事業者が最安の調達先として返る

| 項目 | 判定 |
| --- | --- |
| 優先度・観点 | P1。正確性。正しい形の確認済み見積で、担当者が必要品をまとめて注文できない会社を選んでしまう。 |
| 対象 | [selection.py](../../supplier-selection/selection.py) の `select_supplier`、3–5行。契約は [README](../../supplier-selection/README.md) の3–7行。 |
| スナップショット | [4ファイルの SHA-256 と HEAD](../coverage.md#対象の固定) |
| テーマ・由来 | 単一の事業者に一括注文するための選定。指定パスの現行実装。既出の「未確認の見積も選定に混じる」は2行目で修正済み。今回の不備は確認済み見積だけで発生する。 |
| 採否・適用 | 未判断、未着手。契約に沿って通常入力の誤った返却値を変更する。依存する指摘なし。 |

## 問題と根拠

必要品を机と照明、確認済みの Z 社を机のみ・10、A 社を照明のみ・20とする。誰にも一括注文できないので期待値は `None`。実際は Z が返る。さらに A だけが机も扱うようにすると、担当者が選ぶべき会社は A へ変わるが、実際は依然 Z が返る。両例とも、3行目は品目ごとに別の会社で充足を認め、4行目は確認済みの全社を価格比較している。[実測](../evidence/results.txt)

## 改善案

候補を「確認済みで、その会社自身の扱う品目に今回の必要品がすべて含まれる見積」と定め、入力順を保って抽出する。その集合が空なら `None`、それ以外はその集合内で提示金額が最小の見積の ID を返す。適格社が存在するかを確かめるだけでは、安い部分対応社を除外できない。価格比較に使う集合まで同じ条件を通す。

## 振る舞いへの影響

一括受注できる確認済み会社がない場合、分割すれば全品が揃っても注文先を提示しなくなる。適格社があれば、その中の最安値が分割受注の見積より高くても適格社を返す。既存の確認済み条件、見積一式の価格、同額時に入力順で選ぶ挙動、ID または `None` を返す関数契約は維持できる。修正対象は選定関数内に収まる。

## 検証方法・証拠

現行版を [再現スクリプト](../evidence/replay.py) で実行した。上記2例の不一致を確認済み。Z が全品・10、A が照明のみ・20の対照では正しく Z を返す。修正後は3例で順に `None`、A、Z を確認する。未確認の完備社が最安でも候補から外す例、複数の完備社から最安を選ぶ例、同額の完備社の前後に部分対応社があっても適格社間の順序を守る例も照合する。現行の不一致が修正後に解消したかは未検証。
