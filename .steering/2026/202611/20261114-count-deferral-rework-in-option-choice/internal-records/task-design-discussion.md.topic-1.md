# 内部検討記録: 論点1 — 延期の費用を数える原則を、思考標準のどこへ、どの文面で足すか

**discussion:** [task-design-discussion.md](../task-design-discussion.md)

**論点:** 論点1

## 開始context

- 問題: 「後からでもできる」を、今やらなくても失うものが無い根拠として使い、延期の間に今の形を前提に作られるものの書き換えを見落とす失敗があった（design.md の「元の依頼内容」）。思考標準に、この失敗を防ぐ原則が無い。
- 決める範囲: 追記する file、位置、見出し、文面。
- 開始時の既決条件: 利用者は引き渡しに合意した。中身は未合意。
- 残る不足: なし。

<a id="iteration-0"></a>

## イテレーション0: 置き場と文面

<a id="iteration-0-record-1"></a>

### 判断: どの場面 file の、主軸か補助か

- 場面: 案を比べて選ぶ時の判断であり、「案を作る・提示する・選ぶとき」（`making_and_choosing_options.md`）に当たる。
- 範囲の照合（`naming/core.md` の「中身を足す前に、名前が約束する範囲に入るかを確かめる」）: file 名と README の一行「材料が枯れていないと、案も作れず、選ぶこともできない」は、案を選ぶ時の判断材料を扱う。延期の費用は、案を選ぶ時に見落としやすい判断材料であり、範囲に入る。
- 主軸か補助か: 主軸は「材料が枯れているか」の一つで、延期の費用は特定の形（今やるか後でやるか）の案にだけ効く。主軸を説明する手順ではなく独立した補助判断なので、「補助:」の節にする（`evolution_policy.md`）。
- 位置: 既存の「補助: 提案が暫定か恒久かを示す」の直後。どちらも「今はやらない」判断を扱い、あちらは提示の仕方、こちらは延期の費用の見積もりである。
- 既存の「提案を出す前に確かめる」の三つの確認（「この判断は今決める時期か」等）へ四つ目として足す案は採らない。三つの確認は提案を出す前の材料確認であり、延期の費用は案同士を比べる時の判断である。また、その節は「三つは実際に起きた失敗の形」と数を限定している。

<a id="iteration-0-record-2"></a>

### 判断: 文面の構成

- 既存の補助節の型（やってしまいがちな行動、それをやると何が起きるか、正しい判断のための問い）に揃える。
- 実際に落ちた形（利用先固有の名前を除いた引き渡しの具体例）と、文脈を離れた例（DB の列名）を置き、抽象と具体を往復できるようにする。
- 適用境界: 前提に作られるものが無い場合は 0 と数え、「後からでもできる」がそのまま成り立つことを書き、誤適用（何でも今やる方へ倒す）を防ぐ。
