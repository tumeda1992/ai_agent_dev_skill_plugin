## 論点1: 延期の費用を数える原則を、思考標準のどこへ、どの文面で足すか

**ステータス:** 反映済み

**種別:** TBDヒアリング

### イテレーション0（論点1）: 置き場と文面

#### 提案0（論点1）

`plugins/tumeda-dev/docs/think_standards/making_and_choosing_options.md` の「補助: 提案が暫定か恒久かを示す」の直後（「正しい判断のための問い」の前）へ、次の補助節を足す。

```diff
 - 正しい判断のための問い: 「この提案を受け取った人は、ずっとやらない判断と読まないか」
 
+## 補助: 「後からでもできる」は、延期の間に作られるものを数えてから使う
+
+ある変更を今やるか後でやるかを比べるとき、「後からでもできる」が今やらない理由になるのは、後でやる費用が今と変わらない時だけである。延期の間に、今の形を前提にして作られるものが増えると、後でやる時はそれらも直すことになり、費用はその分だけ増える。
+
+実際に落ちた形を書く。
+
+> application を repository の root に置いたままにするか、subdirectory へ移すかを比べた。
+> 「移動は後からでもできる。今やらないと困ることは無い」として、root に残す案を推した。
+> 後で移すと、それまでに作る container の build 設定、CI の workflow、infrastructure as code が参照する path を、
+> もう一度書き換えることになる。それを見落としていた。見直した結果、container の設定をどのみち作り直す今の作業で移す案に変わった。
+
+文脈を離れた例で確かめる。DB の列名を「後で直せる」として残すと、直すまでの間に作る query、API、別の app がその列名に依存し、直す時に全部を書き換えることになる。
+
+前提に作られるものが無いなら、数えた結果は 0 であり、「後からでもできる」はそのまま成り立つ。独立した文言の修正などがこれに当たる。この補助は、何でも今やる方へ倒すためのものではない。
+
+- やってしまいがちな行動: 「後からでもできる」を、今やらなくても失うものが無いことの根拠として使う
+- それをやると何が起きるか: 比べた時点の費用で判断するため、延期の間に今の形を前提に作られるもの（設定、参照する code、蓄積するデータなど）の書き換えが、後でやる費用から抜け落ちる。後になるほど費用が上がる案を、安い案として選ぶ
+- 正しい判断のための問い: 「今やらなかった場合、やるまでの間に、今の形を前提に何が作られるか。それを直す費用を、後でやる費用に含めたか」
+
 ## 正しい判断のための問い
```

あわせて、適用時に次を行う。

- `scripts/verification/validate-plugin.mjs` に、追加した見出しの `requireText` を、既存の `## 補助: 提案が暫定か恒久かを示す` の検査の直後へ足す。
- 配布 version を `8.3.2` から `8.3.3`（PATCH。docs の追加）へ上げる。宣言値 4 か所と `expectedRelease`。

#### 検討記録（論点1・イテレーション0）

**置き場:** 案を比べて選ぶ時の判断なので、場面「案を作る・提示する・選ぶとき」に当たる。この file の名前と README の一行は「案を選ぶ時の判断材料」を約束しており、延期の費用はその判断材料として範囲に入る。

**補助にする理由:** この場面の主軸は「材料が枯れているか」の一つで、延期の費用は今やるか後でやるかという形の案にだけ効く独立した判断である。思考標準の維持規律（`evolution_policy.md`）は、主軸を一つに保ち、独立した補助判断に「補助:」を付けると定めている。

**位置:** 既存の「補助: 提案が暫定か恒久かを示す」の直後にした。どちらも「今はやらない」判断を扱い、あちらは提示の仕方、こちらは延期の費用の見積もりである。

「提案を出す前に確かめる」の三つの確認へ四つ目として足す形は採らなかった。三つの確認は提案を出す前に前提と時期を確かめるもので、延期の費用は案同士を比べる時の判断である。また、その節は「三つは実際に起きた失敗の形であり、網羅のために足したものではない」と数を限っている。

**文面:** 既存の補助節の型（やってしまいがちな行動、何が起きるか、正しい判断のための問い）に揃えた。実際に落ちた形は、引き渡された具体例から利用先固有の名前を除いたもので、文脈を離れた例（DB の列名）と合わせて抽象と具体を往復できるようにした。「何でも今やる方へ倒す」誤適用を防ぐため、前提に作られるものが無ければ 0 と数えて「後からでもできる」が成り立つ境界も書いた。

### 決定（論点1）

`plugins/tumeda-dev/docs/think_standards/making_and_choosing_options.md` の「補助: 提案が暫定か恒久かを示す」の直後へ、提案0 の diff のとおり「補助: 「後からでもできる」は、延期の間に作られるものを数えてから使う」を足す。`validate-plugin.mjs` に見出しの `requireText` を足し、配布 version を `8.3.3`（PATCH）へ上げる。

選択理由: 案を比べる時の判断材料なので、場面「案を作る・提示する・選ぶとき」の範囲に入る。主軸「材料が枯れているか」とは独立した判断なので補助にする。「提案を出す前に確かめる」の三つの確認は数を限っており、延期の費用は案同士を比べる時の判断なので、そこへは足さない。
