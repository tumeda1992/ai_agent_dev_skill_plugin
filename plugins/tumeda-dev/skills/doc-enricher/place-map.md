# 置き場所の一覧

`doc-enricher` が置き場所を決める時に使う、repositoryごとの一覧である。そのrepositoryにどんな文書があり、それぞれが何を扱うと約束していて、いつ読まれるかを並べる。

毎回の作業で調べ直さないよう、一度作ってrepository固有文脈へ保存し、使い回す。調べ直すと、作業のたびに一覧が変わり、同じ知識の置き場所が回によって変わる。

## 形

| 置き場所 | 約束する範囲 | 読まれる時 |
| --- | --- | --- |
| path。同じ役割の文書が多数ある時は「各module directoryの `README.md`」のようにまとめて一行にする | その文書が扱うと約束している対象。文書の名前と入口の説明から取る | 誰が、どの作業の、どの時点で読むか。何がその文書を読ませるか（作業の決まりの指示、skillの手順、場所の近さ） |

架空のrepositoryでの例を示す。

| 置き場所 | 約束する範囲 | 読まれる時 |
| --- | --- | --- |
| `AGENTS.md` | repository全体の作業の決まり | すべての作業の開始時に必ず読まれる |
| `docs/architecture.md` | すべてのmoduleのcodeの構造の決まり | 設計の前に読むことが、作業の決まりで定められている |
| `docs/domain/<領域>/` | その領域の業務の決まり | その領域の仕様を調べる時に、索引から辿る |
| 各module directoryの `README.md` | そのmodule | そのdirectoryのcodeを読む・変える時に、近くにあるので開く |
| codeのcomment | その一箇所 | その行を読む時 |

「約束する範囲」は `SKILL.md` の進行4で測った範囲と照合するために使い、「読まれる時」は範囲の合う文書が複数ある時に選ぶために使う。

## 作り方

1. プロジェクト指示（作業の開始時に読まれるfile）を読み、そこから読むよう指示されている文書を辿る。
2. 文書群の索引（docsのREADME等）を読み、各群が何を扱うと書いているかを取る。
3. directoryごとのREADMEを置く習慣があるかを、いくつかのdirectoryで確かめる。あれば、一つずつ並べずにまとめて一行にする。
4. 「約束する範囲」は、その文書の名前と入口の説明に書かれたことから取る。中身を読んで推し量らない。「読まれる時」が確かめられなければ「不明」と書く。
5. `maintenance-plugin-context` へ、consumer=`doc-enricher`、保存する一覧、確認元（読んだ文書のpath）を渡し、doc-enricherの節への保存を依頼する。

すべての文書を並べなくてよい。文書群と、同じ役割の文書のまとまりが一行ずつあれば足りる。

- やってしまいがちな失敗: repositoryのMarkdownをすべて列挙する。「約束する範囲」を、今回置きたい知識に合わせて広く書く
- それをやると何が起きるか: 一覧が長くなり、範囲の照合に使えなくなる。どの文書にも何でも置ける一覧になり、置き場所を決める役に立たない
- 判断の問い: 「この行の『約束する範囲』は、その文書の名前と入口の説明のどこに書かれているか」

## 直す時

一覧に無い文書群を見つけた時、文書群が増えた・無くなった時は、同じ依頼で直す。`doc-enricher` の提案で新しいfileを作った時は、既存の行に含まれるなら直さない。
