# 元作業に限定する暫定指示の管理

暫定指示の登録・改訂・取得・終了を依頼された時だけ、この内部指示を読む。
管理担当はmaintenance-plugin-context。同じ担当が記録と選択・競合・版・終了を一箇所で扱い、consumerは判断を複製しない。
安定したrepository factのinstanceと暫定指示は、依頼・保存先・返却を独立させる。

## 元作業と依頼を確認する

依頼の目的、元作業のexactなdirectoryと同じ作業である根拠、consumer skillと対象処理、実際に実行するSKILL.mdの取得元を受け取る。
不足は元の担当へ返し、別作業を探索しない。元作業が未確定ならその担当が確定してから取得する。
Git rootやrepository共通の置き場を元作業と推定しない。

指示は元作業の`temporary-overrides/001-<短いkebab-slug>.md`へ保存する。
必要になった時だけdirectoryを作り、同directoryの最大連番+1を3桁以上にする。再利用・自動改名・global ID化はしない。
一指示一fileとは、独立して改訂・終了できる指示の単位である。一発言・一skillでは区切らず、複数skillに効く同じ指示を複写しない。
終了済みも同じ場所へ残す。別作業へ自動継承せず、別作業で使うには新しい指示を受ける。

安定factの`.agents/skills/tumeda-dev-plugin-context.md`、配布template、repository共通の場所へ動作ルールを混ぜない。
fact依頼がなければinstanceの作成・更新へ進まず、空のfact instanceを作らない。
pending-escalationsは提案の控えであり、その存在や受領だけでは暫定指示を成立・終了させない。

## 記録を登録・改訂する

利用者が指定した動作を、実際の指示原文と出典に結ぶ。agentが作った改善提案から有効な指示を補完しない。
[暫定指示の保存部品](templates/temporary-override.md)を使い、次を同じfileへ保存する。

- 元作業の同定情報、利用者の原文と出典、対象skill・処理・条件、現行の動作、明示された終了条件。
- 有効／停止／終了の適用状況、確認した実行pluginのversion・取得元・根拠、未解決事項。
- 登録・改訂・停止・継続・終了の履歴。変更前後、実際の指示・判断・証拠を残す。

登録時は既存fileの未作成を確認する。改訂時は既存本文と履歴を読み、同じ指示の意味と出典を確認する。
現行の動作は更新できるが、以前の意味と原文を履歴へ保存してから変更する。
「最初から同じ指示だった」ことにせず、過去の指示原文や判断根拠を消さない。
関連する保留メモがあれば参照できるが、同じ内容の正本を複製しない。
保存直前に対象fileを読み直し、保存後に同じfileと差分を確認してから返す。

同じsessionで登録・更新・終了した場合は、管理担当から現在の対象consumerへ更新後の内容と読直しの必要を返す。
通知されていない編集の即時発見、未更新の旧版skillによる自動取得は保証しない。background監視や別sessionの自動起動は追加しない。

保存した出典を辿れることを確認する。
出典をfile linkにした時は、保存先fileから相対pathを実解決し、対象fileと指定anchorの存在・原文の対応を確認する。
入力を読んだ時のcwdから相対pathをそのまま写さない。
会話上の原文が出典なら、実際の発言・応答を識別して原文を残す。実在しないfile・anchorを作ったことにせず、file化されていない会話を架空linkで表さない。
改訂や追跡更新でも同じ確認を行い、出典を取得できない場合は確認不能な範囲を返す。

## 適用候補と実行版を照合する

取得時は元作業内の全候補を読み、元作業・対象skill・処理・条件に一致する指示を選ぶ。
終了済みは実効指示から除外する。作業directoryが読めない、候補の列挙・読取が失敗する場合は「指示なし」にしない。
別作業の指示は読み広げず、その作業の記録へ持ち込まない。

同じ対象に効く指示を全て照合し、上位指示、安全・権限の制約、確認済みのrepository factを上書きしない。
利用者が置換・取下げを明示していれば、その範囲で改訂・終了する。
並立できない指示が残れば矛盾する箇所と影響を示して対象の暫定動作だけを止め、必要な判断を返す。
新しいfileの自動優先や、指示の意味を一部ずつ切り取った合成はしない。

実行versionは、実際に使うSKILL.mdの取得元と同じ配布単位のmanifest宣言で確認する。
同じ配布単位の宣言が食い違う、実行元を特定できない、または必要な宣言を読めない場合は確認不能とする。
repositoryの最新版とcacheを取り違えず、上流のrelease・merge・保留メモの引渡しだけで実行版が変わったとは扱わない。
候補に適用する必要がある実行版を確認できない時はunavailableとし、記録済みversionを実測値の代わりにしない。

確認済みの実行versionが記録時から変わったら、影響する暫定動作をいったん停止する。
実際の変更を確認し、対象規則が不変の無関係な更新でも継続してよいか利用者へ毎回尋ねる。
利用者の回答を原文・出典と共に履歴へ保存し、継続が明示された範囲だけ確認版を更新する。
同じ作業・同じ版で有効な指示を再取得するたび、継続を問い直すことはしない。
版更新による停止と終了は区別する。全面代替が既に確認できる場合の終了は下の終了処理へ進める。

## 実効指示または停止理由を返す

安定factとは別の節で、該当する状態と根拠を返す。

| 状態 | 条件と後続 |
| --- | --- |
| active | 元作業・対象・条件・版を確認した指示。consumerは返された実効指示を使う |
| none | 元作業と候補の列挙を確認し、該当する有効指示がない。取得失敗を含めない |
| paused | 競合や版更新等で適用を停止。矛盾・変更・必要な判断を返す |
| unavailable | 所在・読取・必要な実行版等を確認できない。不足と影響を返す |
| ended | 今回終了を記録・通知した。終了済み本文は実効指示に含めない |

状態に加え、指示のpathと改訂、対象・条件、実効指示、実行版の取得元・確認根拠、停止・終了理由を示す。
複数の独立指示があれば各結果を区別し、一つの停止で無関係な指示まで止めない。
指示を取得しただけで合意や有効性を認定しない。
止めるのは影響する暫定動作であり、指示を無視した通常動作へ黙って切り替えない。
無関係な作業と安定factの取得は続ける。consumerの既存writer・完了判定は移さない。

実際の新規起動、別sessionからの再開、resume、把握した変更時にこの処理を使う。
通常の返信、think-throughの毎turn適用、内部指示fileの読直しを定期取得の理由にしない。

## 終了を記録する

利用者の明示取下げ、明示された期限・終了条件の成立を根拠に終了する。
終了時期の別指定がなければ、元作業の完了または実際の正式版による全範囲の代替でも終了する。
元作業の完了は既存の担当が判断・記録し、この管理担当へ通知する。
一返信、一skill呼出し、session終了、中断、承認待ちは元作業の完了ではない。管理担当独自の完了判断や追加の完了承認gateは作らない。

正式版による全面代替は、実際に使う正式版が指示の対象・動作・条件の全てを満たすと確認できた時だけ認定する。
複数skillに効く指示はその全範囲を照合する。根拠を記録して終了し、同じ終了への追加承認は求めず切替を報告する。
merge・release済み、同名機能、一部修正、取得不能だけでは全面代替にしない。
部分代替・証拠不足では残る差と必要な判断を返し、一部だけ残す自動分割・改訂、過去の意味の書換えは行わない。
全面代替による終了は、版更新時の自動継続を許す規則ではない。

終了時は同じfileに状態・理由・根拠を記録し、変更前後を履歴へ残して適用候補から外す。
fileは削除せず、同じ作業を後日再開しても自動復活させない。必要なら新たな利用者指示を受ける。
結果は元作業の担当と対象consumerへ返す。保留メモの引渡しだけで終了にせず、保留側の進捗同期も追加しない。
