# Skill構造review

## 作業限定の暫定指示を取得する

起動・別sessionからの再開・resume・把握した指示変更時に、元作業のexactな場所、consumer `skill-update-review`、
対象処理、実際に使うこのSKILL.mdの取得元を`maintenance-plugin-context`へ渡し、暫定指示を取得する。
選択・競合・実行版の判断は管理担当へ委ねる。
activeの実効指示に従い、paused/unavailableでは影響する暫定動作を止めて理由を返す。
none/endedでは既存処理へ進む。
元作業不明を別作業の探索で補わない。
通常の返信・内部file再読・think-throughの毎turn適用を定期取得へ変えない。
同一sessionの登録・改訂結果は返却された更新を使い、通知されていない編集を常時検知できるとは扱わない。


構造案の採用前と、skill-creatorによる編集後に明示適用する。構造の合格は、利用者の合意、機能・安全・独立した動作検証、作業完了の合格を代替しない。
編集そのものはskill-creatorと元の担当が行う。

元作業directoryが未確定なら、取得不能をnoneにせず管理担当へ不足を返す。
既存ownerによる命名・directory確定に必要な処理は続け、影響する暫定動作だけを待ちにする。
元作業が確定した直後に取得し、先に対象の暫定動作を実行しない。

## 入力と対象判定

対象の入口path、新規／更新、設計時／編集後、目的・変更内容・保持する要件と根拠、資料・更新前の比較元、再review時の先行指摘、元作業と返却先を既存contextから揃える。
専用依頼file、利用者の手動記入、固定構文は要求しない。

起動条件、指示、入出力、役割分担、参照・読取条件、scriptの動作を変える更新が対象となる。誤字・書式だけの変更は、差分と参照先から意味・構造不変を示せる時だけ除外できる。
file種類・行数・「軽微」という呼び名では除外しない。不明な変更、明示review、既知の不合格、既存の合意・検証条件を省略しない。

設計時には予定入口と構造案を認め、実行指示・script全文の先行完成を要求しない。既存更新では現行一式も確認する。編集後には実物一式、構造案、実在する更新前後の比較材料を使う。
同じ設計・編集agentが明示適用してよいが、別途指定された独立review・動作検証は維持する。

## 進行

1. [材料収集](collect-review-material.md)で入力・比較元を揃え、実物と必要な依存を読み、取得元・範囲・内容を識別する。読んで埋まる不足は自ら確認する。
2. [全体評価](assess-structure.md)で対象全体を判定し、先行指摘と現物全体を再確認する。既知の問題と未確認が併存する時は両方を返す。
3. [結果の部品と例](templates/review-result.md)を使い、返却前に確認材料の版を照合する。呼出し側の既存記録とwriterへ結果を返す。

不足・不合格を残したまま通常完了へ進まない。構造reviewだけで実装を自動再開せず、元のworkflowへ戻す。別作業の探索、外部連絡、読取許可から広げた実行・生成・編集は行わない。

## 既存結果の再利用と再review

返却前と、callerが次工程・再開に判定を使う時に、読取集合・追加削除・参照・解決先・必要な前提の変化を照合する。
可変なlocal sourceは内容hashで識別し、skill名・version・commitだけで未commitの実物の一致を認定しない。

意味・構造不変と示せる表記修正、共有先の未使用の独立節だけの変更は、無影響の根拠と差分を記録して判定を維持できる。構造・必要な前提が変化したら対象全体と必要な依存を再reviewする。
影響不明や必要資料不足なら追加確認へ戻し、旧合格を使わない。旧判定は履歴として残す。

hashは読了・合格・機能検証・実在する比較元の代替ではない。各返信での監視、全repository追跡、排他lock、将来の配布・導入・実行内容の一致は保証しない。
