### 文書にまとめる知識と、その保ち方

<!--
移行元:
- 旧templates/design.md「docs・設定・環境構築系 deliverable」
- task-design/SKILL.md「観点4」
- 旧軽量modeが扱っていたdocs作成・更新task

documentationの新設、組み直し、本質的な更新によって、読者がcodeや過去の会話を探し直さずに判断・実行でき、
意図した知識の内容を最新に保てる状態を設計する。

なぜ必要か:
- 「READMEを整備する」「標準を書く」というfile名だけでは、実装者が何を抽象化し、どの判断の力を作るかを独自に決めるため。
- 暗黙知や個別の困りごとをそのまま事例集にせず、別のcaseでも使える原則、判断の問い、具体例、失敗例へ引き上げるため。
- どれを正として直すか、誰がいつ直すかが決まっておらず、書いた時点では正しかった内容が古くなるのを防ぐため。

NG:
- READMEを整備する
- 標準を書く
- 利用者のfeedbackや具体ケースを、そのまま一般則として保存する
- 原則だけを書き、判断の問い、具体例、失敗例、当てはめる範囲を持たない
- 同じ知識をREADME、docs、skillへ重ねて書く
- 書いた時点の内容だけを置き、直す人と、古くなったと気づく条件を決めない

具体的な記述例:
docs/architecture.md:
- 構成: (1) 各layerとその責務 (2) 各layerの判断基準 (3) 避けるべき形と正しい問い
- 形式: Markdownで、layerごとにh2見出しを置く
- 配置: docs/
- 読者ができるようになる判断: 新しい責務をどのlayerへ置き、何を置いてはいけないかを、codeを調べ直さずに判断できる

function migration policy:
- 文書にする困りごと: file分割の時に見出しだけが移り、理由、例外、失敗例が落ちる
- できるようにする判断: 移行する人が、移行前の記述を意味の単位へ分け、合意の無い削除を止められる
- 知識の並べ方: 目的 → 不変条件 → 意味の単位 → 移行の対応表 → 先へ進む条件 → 失敗の型 → 例
- 決まり: 全ての範囲の登録と、分類されていないものがzeroであることはMUST。単なる行数の比較は補助の目安であって、完了の証拠ではない
- 内容を最新に保つ方法: workflowや、skillの間の受け持ちの境目を変えた時に、policyと、それを使うskillを同時に確認する

記述のMUST:
- 文書にする暗黙知、散らばった知識、繰り返し起きた困りごとと、具体例から引き上げる、再び使える原則を示す。
- 読者と読む場面、および読んだ後にcodeや過去の会話を調べ直さずにできるようになる判断または作業を示す。
- 概念、原則、判断基準、具体例、失敗例、手順、参照を、抽象と具体を往復できる構造で並べる。
- 決まりの理由、MUST／SHOULD／MAY、当てはめる対象、例外、非目標、誤った当てはめを示す。
- 保つべき内容、正とする記述の置き場所、直す人、直すきっかけ、古くなったと気づく兆候、関連するdocsとの重複を防ぐ方法を示す。
- 完成後のpath、見出し、項目、参照関係、具体例の配置を示し、既存documentへ統合するか、新しいdocumentを作るかの理由を明示する。
  - 統合する時は、統合先の範囲に入ることを [`naming/core.md` の「中身を足す前に、名前が約束する範囲に入るかを確かめる」](../../../../docs/development_standards/naming/core.md#中身を足す前に名前が約束する範囲に入るかを確かめる) で確かめ、その結果を理由に含める。

判断基準:
- 読者が、記録された具体ケース以外にも同じ原則を当てはめられるか。
- 抽象的な標語と個別の事例の間を、判断の問い、例、失敗例で往復できるか。
- どこまで決まりが当てはまり、どこから例外または非目標かが一意か。
- 元になった事実が変わった時、誰が何を兆候としてこのdocumentationを直すか分かるか。
- 内容、配置、形式だけでなく、documentationだけを作る作業で完成後に変わるものが、完成後の状態として読めるか。

| --- | --- | --- | --- |
| {読者} | {場面} | {判断または作業} | {最初に開く場所} |

**知識の並べ方:**

```text

```

**決まりの理由と、当てはめる範囲:**

- 理由になる困りごと・失敗: {なぜこの決まりが必要か}

- SHOULD: {原則として守ることと、例外の条件}
- MAY: {任意の選択}
- 当てはめる対象: {範囲}
- 例外・非目標: {当てはめない範囲}
- 誤った当てはめ: {似ているがこの決まりを使わないcase}
