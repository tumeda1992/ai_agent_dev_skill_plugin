# 明示された改善の保留と再開

この内部指示はescalate-plugin-skill-fixの保留判定・条件付き再開を所有する。
利用者の明示保留を受けた時、または同じ元作業の保留メモから再開する時だけ読む。
保留の保存・追跡後は同じ元作業の担当へ返し、実際の引渡しだけを入口の既存escalationへ戻す。

## 保留を保存する

plugin repositoryへ作業対象を切り替える前に、実際の利用者指示を確認する。
「この改善は後で」という個別保留と、「この作業中の改善は全部後で」のような対象・期間付きの指示を扱う。
範囲・期間が不明なら不足だけを確認し、慣習、agentの方針文書、既存メモの存在から保留を補完しない。
plugin内で作業している場合も同じ判定を行う。明示保留がなければ既存の即時引渡しへ戻す。

元作業のexactなdirectoryを元の担当から受け取り、未確定なら先に記録場所を定める。
特定できない時は担当へ戻し、別作業の探索やrepository共通の仮置きはしない。
`pending-escalations/`は必要になった時だけ元作業内へ作る。
同directoryの最大連番+1を3桁以上にし、内容から選んだ短いkebab-case slugで`001-<slug>.md`の形にする。
番号の再利用・自動改名・global ID化は行わず、既存fileは上書きしない。

[保留メモ](templates/pending-escalation.md)の必要な部品を使い、一改善一fileで保存する。
「保留時の内容」は提案・具体例・根拠・保留指示の原文と出典・対象・再開条件を保存し、初回保存後に固定する。
後からの訂正・追加証拠・別提案は元の議論へ記録し、「関連情報」に所在と影響を追記する。
固定本文を現行の結論へ上書きせず、メモを第二の議論場所にしない。
元の議論からメモの相対pathを参照し、追跡には保留状態と未実施の引渡しを記す。

保留指示はその対象・元作業だけに効く。別作業の保留、暫定動作の変更、実装、公開の権限へ広げない。
暫定動作の指示が別にあればmaintenance-plugin-contextへ渡し、保留メモだけで指示を作成しない。

保存した出典を辿れることを確認する。
出典をfile linkにした時は、保存先fileから相対pathを実解決し、対象fileと指定anchorの存在・原文の対応を確認する。
入力を読んだ時のcwdから相対pathをそのまま写さない。
会話上の原文が出典なら、実際の発言・応答を識別して原文を残す。実在しないfile・anchorを作ったことにせず、file化されていない会話を架空linkで表さない。
改訂や追跡更新でも同じ確認を行い、出典を取得できない場合は確認不能な範囲を返す。

## 再開条件を確認する

同じメモの固定本文・関連情報・追跡と、現在の元作業・実際の発話を併読する。
「設計が終わったら渡して」は同じ作業の設計完了の証拠を確認して引渡しへ進む。
「終わったら渡すか聞いて」は条件成立後の実際の回答を待つ。
「今は保留」は解除指示を待ち、「落ち着いたら」など成立基準が不明な指示は必要な意図だけを確認する。
対象・条件が元の指示で明確なら、同じ採否を聞き直さない。

追跡に元の指示と条件成立の証拠、必要な実応答の所在を残す。
後の保留継続、範囲や権限の変更、証拠不足があれば古い条件で押し切らず、元の指示で覆えない判断へ戻す。
background監視、sessionの自動起動、追加のcommit・公開権限は加えない。

## 現在の提案を引き渡す

固定本文をそのまま現行事実として送らず、後発情報と現物から現在妥当な提案・具体例・根拠を整える。
入口の既存の汎用化・repository判定・steering起動を使い、別の転送processを作らない。
plugin側へは利用先固有情報を除く既存規約を適用する。意味を保てない場合の停止も維持する。

再開前に追跡の既存転送先を確認する。既に同じ作業が作られているならその受領を確認し、二重起動しない。
転送先を作っただけ、または起動・記録に失敗した段階では「引渡し中」と未完範囲・理由を残す。
元作業を切り替える前の保留判断と、既存の実際の引渡しの責務を混同しない。

## 受領先を記録する

plugin側が提案を受領し、その作業記録へ辿れると実物・応答から確認した時だけ「引渡し済み」にする。
受領先path、確認の根拠と実応答、現在の未完理由を追跡へ保存し、メモは同じ場所へ残す。
受領前の停止・失敗では保留または引渡し中を維持し、再開時は保存済みの先へ戻る。

引渡し済みは改善済みではない。修正・release・利用先導入の進捗同期を必須にせず、必要時はplugin側の記録を読む。
引渡しを元作業の再開・完了への新しいgateにしない。暫定指示の自動終了も行わない。
同じ元作業へ結果とメモの場所を返す。元作業の担当と既存の議論writerを増やさない。
