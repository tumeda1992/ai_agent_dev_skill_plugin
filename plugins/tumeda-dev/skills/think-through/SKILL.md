# think-through スキル

## 作業限定の暫定指示を取得する

起動・別sessionからの再開・resume・把握した指示変更時に、元作業のexactな場所、consumer `think-through`、
対象処理、実際に使うこのSKILL.mdの取得元を`maintenance-plugin-context`へ渡し、暫定指示を取得する。
選択・競合・実行版の判断は管理担当へ委ねる。
activeの実効指示に従い、paused/unavailableでは影響する暫定動作を止めて理由を返す。
none/endedでは既存処理へ進む。
元作業不明を別作業の探索で補わない。
通常の返信・内部file再読・think-throughの毎turn適用を定期取得へ変えない。
同一sessionの登録・改訂結果は返却された更新を使い、通知されていない編集を常時検知できるとは扱わない。


元作業directoryが未確定なら、取得不能をnoneにせず管理担当へ不足を返す。
既存ownerによる命名・directory確定に必要な処理は続け、影響する暫定動作だけを待ちにする。
元作業が確定した直後に取得し、先に対象の暫定動作を実行しない。

## repository固有文脈

プロジェクト固有のinstructionが今回の思考・判断へ影響する時は、`maintenance-plugin-context`へconsumer=`think-through`、必要理由、必要fact=`プロジェクト指示`、確認元候補を渡す。返された範囲だけを読む。返されない時はrepository固有の規約を推測せず、このskillの一般原則だけを適用する。

## 役割

議論・思考プロセスの作法を矯正する。`.claude/hooks/think_through_session_start.sh`と`think_through_user_prompt.sh`により毎ターンcontextへ注入される。
脊髄反射の応答・浅い診断・場当たり的な変更を防ぎ、思考の深さをそのまま出力に乗せるためのガードレール。

口調（原始人モード）と内容（思考の深さ）は別軸。端的に話すことと、CLAUDE.md・SKILL の指示を無視することは違う。
脊髄反射で受け取らず、一度受け取った後 このファイルの作法で吟味してから返すこと。

リトマス試験紙: この作法ができていないとき、CLAUDE.md やこのスキルの指示を忘れているサイン。
セッション再起動を検討する。

## 思考標準の参照

思考標準の内容の正本は `../../docs/think_standards/` にある。`think_standards/README.md` がハンドリング方針（どの場面で何を参照するか）の正本であり、その引き方に従って該当fileを読む。場面一覧と引き方の手順はここへ複製しない。
