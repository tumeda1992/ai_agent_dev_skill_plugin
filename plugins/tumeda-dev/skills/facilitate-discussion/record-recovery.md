# 未収録議論の回復

## 入る条件と引き継ぐ証拠

[SKILL.md](SKILL.md) の検出gateから、未保存のまま成立したchat合意、または処理を進めた後に発見した記録漏れを扱う。通常の到着直後の応答、reparent・取下げ、正しく保存済みの中断復帰は対象外である。
対象file、未収録範囲、会話履歴、変更前後の成果物、差分、確認済みの保存状態を引き継ぐ。同じownerがsingle writerで実行し、毎回の全体再読込・一意な保存範囲・停止規則はhandlerを使う。

## 記録できる変遷と合意の範囲を確かめる

起点原文、当初の材料と案、条件、応答、誤認、修正案、合意、反映済み成果物を、証拠から時系列に対応させる。各応答は評価した提示と同じ回へ置く。
`続けて`、無反応、異議がなかったこと、抽象的な先行decision、assistantの推論を、未提示の具体案への合意へ変換しない。成果物の存在や差分は実行の証拠であり、案を提示したことや合意の証拠ではない。
保存先はhandlerのscope・所属・原因owner・親子規則で選ぶ。別decisionを一回へ圧縮しない。事後かつchat合意済みなら、一つの再構成内で合意証拠を使い、二経路から同じ履歴を保存しない。

[templates/discussion_entry.md](templates/discussion_entry.md) と [templates/internal_record.md](templates/internal_record.md) の全文を読み、必要なcode blockだけを使う。
新規はmetadataと回、既存は必要な回・欄だけを使い、実在しない段階を追加しない。
応答を伴う提示は、提案なら「空の提案応答欄」、認識合わせなら「空の認識合わせ回答欄」へ「受領応答の本文」を入れる。
本文・検討記録・対応応答の読順で、確認できる原文と結果まで同じ回に保存する。回復のため空の応答待ちを作らない。

### 二層へ戻す内容を分ける

handlerの保存先規則で対象logを解決し、discussionと対象logを全文読む。
一つの論点に正しく接続された既存logがあれば継続し、旧discussion内の経過を一括移動しない。

- 内部logには、実際に辿れる調査・推論・訂正・検証、記録漏れの診断、実施済みactionと確認不能範囲を保存する。
  - `事後記録`と分かる単位で、元記録・chat・差分の所在、なぜ現在の結論に至るかを残す。
  - 既存の完了済み記録を上書きせず、追加した訂正から元の回・記録を指す。
- discussionには、実際の提案・認識合わせ、判断に必要な背景、原文の応答、明示合意を保存する。
  - 未提示の回復案を、過去に提示した案として偽装しない。
  - 過去の提示本文が存在するならその内容を保ち、後の回復説明は新しい回または正当に空いている応答へ置く。
  - 判断に必要な背景と内部logへのlinkを添える。

どちらを書く場合も、直前にhandler指定の `expression_notation.md` を全文読む。

## chat上で成立した合意を記録する

このvariantは、合意前に判断可能なproposalを保存する通常経路の代替ではない。

対象となる具体案とユーザーの明示合意をchatから特定できた場合だけ、再合意なしで記録する。反映済みかどうかは条件を変えない。
確認できる原文・材料・案・条件・応答・誤認・修正を順に保存し、明示合意を対応欄へ置く。合意対象と保存先をhandlerへ返して現在decisionを確定してもらう。固定result schemaは作らない。
同じ合意を取り直さない。ただし記録のため新たな判断が必要になった場合は、追加判断だけを未決に分け、handlerから通常の提示準備へ接続する。
明示合意を特定できなければこの経路で決定せず、事実、未合意案、先行actionを分けて未決として返す。結論要約、変更file一覧、反省だけを議論の記録として扱わない。

## 後から発見した記録漏れを再構成する

通常の次論点より先に、chat・discussion・変更前後・差分を照合する。既存decisionの変更なら同じ論点の回、別decisionなら新論点へ、handlerの規則で対応させる。
`事後記録`、漏れへ気づいた契機、反映済み成果物、確認不能範囲を明記する。あたかも反映前に保存していたように書かない。
ユーザー発言・assistant案・観測事実・合意済みdecision・未合意推論を区別する。具体案への合意を確認できないなら`合意なし`または`確認不能`とし、先行actionはprocess逸脱として残す。後から書くことで正当化しない。
chatや変更前状態を失っている時は、その限界を示して補完しない。存在しなかった提案・回答・合意・段階は創作せず、存在しなかったこと自体を記録する。
旧履歴と結果だけでなく、確認できる変遷を残せたかを確認する。新しい解釈で過去の応答を上書きしない。

## 回復結果からhandlerへ戻る

保存済み履歴、具体案と明示合意、残る未決、未同期・確認不能を分けて返す。handlerは実stateを再評価し、一decisionずつ確定・consumer反映・全体再評価を通す。
通常同期と返却gateはhandlerが所有する。回復だけで次の論点へ進めたり、適用可能な未保存decisionを返したりしない。書込み不能や対象不明は停止し、未同期範囲を報告する。
