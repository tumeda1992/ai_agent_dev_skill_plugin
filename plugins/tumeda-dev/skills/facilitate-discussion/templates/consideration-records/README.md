# 検討記録のformat

## 検討記録が支えるもの

このdirectoryは内部検討記録の目的別format guideであり、discussion entryへ丸ごとcopyする雛形ではない。説明・実施前の開始形・結果後の読み方・具体例を持つ。
調査や判断の実行順序は [../../iteration.md](../../iteration.md)、logの所属・回・記録単位は [../internal_record.md](../internal_record.md)、案の表示はproposal-sectionsが所有する。
discussion側の「検討記録」は、この蓄積から判断に必要な因果へ再構成する背景である。経過を移す先でも、内部logへのlinkだけを置く欄でもない。
ここで材料の充足判定やdiscussionの状態遷移を代行しない。

## 今の目的に合う記入形を選ぶ

新しいblockの目的から一つを選び、該当file全文を読んで入力を保存する。目的変更時も選び直す。全fileを毎回読む必要はなく、既存根拠を判断する回に形式だけの調査を足さない。

| 目的と判断材料の変化 | 記入形 |
| --- | --- |
| 問いに対して外部sourceから事実と探索限界を得る | [research.md](research.md) |
| 必須条件・評価軸へ案を当て、推奨と代償を定める | [judgment.md](judgment.md) |
| 事実と読解を分け、user所有の未共有前提を特定する | [alignment.md](alignment.md) |
| claimを方法と合格条件に照らし、支持できる範囲を定める | [verification.md](verification.md) |
| 期待との差から原因と修正先を特定する | [diagnosis.md](diagnosis.md) |
| 起点caseから原則を取り出し、異なるcaseで境界を育てる | [generalization.md](generalization.md) |

同じ作業に複数の目的がある時は、調査のfindingを判断が参照する等、意味の変わる位置でblockを分ける。短い補足まで機械的に分割しない。

## どの記入形でも辿れるようにすること

目的と具体対象が分かるsemantic titleを使う。`確認N`、`検討内容`だけのlabelにしない。共通なのはsyntaxでなく、目的・根拠・言える範囲・次への接続を辿れることである。
目的に必要な情報の対応を保てば、見出し名や表・散文を調整してよい。未確認と該当なしを分け、空の欄や成立前の結論で体裁を揃えない。生log、資料全文、tool回数を記録の厚みの代用にしない。
各fileの例は記入方法の例であり、実際の調査・検証結果ではない。

内部logの開始contextと合わせて、何の問題をどの範囲で扱い、何を確かめ、何が判明・否定・未確認になり、なぜ次へ進んだかがlogだけで理解できる情報量を持たせる。
短さやformatの充足だけを理由に、問いと証拠の因果を省略しない。表や見出しへ構造化する時も、事実と解釈の違いは保つ。
各fileの例にある見出し深度は固定ではない。実行側が内部logの記録単位へ合わせ、目的別の構成は維持する。

## 目的を変える時は根拠を引き継ぐ

完了したblockは変えず、後続blockから必要なfindingを特定して参照し、新しい評価・解釈を加える。原文や表を二重管理しない。新evidenceで訂正する時も元の結論と置換理由を新blockに示す。
完成時に結論を先に読ませる目的では、取得後に結論を冒頭へ加える。これは後付けの過程創作ではなく、実施前入力と結果の保存を保ったまま読順を整える操作である。

## 該当する形がない場合

六用途に押し込まず、上の読み取りcontractを満たす内容固有の形を使う。
その場合は、何を確定する目的か、既存formatではどの必要情報を表せないかを記録し、実例から不足する目的を検討する。
見出し名や記法の調整で表せるなら既存formatを使い、見出しが不便というだけで未該当としない。
必須fileが読めないことを未該当と呼んで迂回しない。
