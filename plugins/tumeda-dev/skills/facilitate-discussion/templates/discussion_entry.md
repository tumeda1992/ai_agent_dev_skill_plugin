
# 議論記録の保存形

## 論点metadata

```markdown
## 論点N: {判断内容を表すタイトル}

**ステータス:** {調査中 / 応答待ち / 依存先待ち / 子論点待ち / 決定 / 保留 / 分解済み}

**親論点:** 論点M

**種別:** {TBDヒアリング / 認識齟齬 / レビュー指摘。複数可}

**重さ:** {一つずつ考える / まとめて考える / 確かめるだけ}（{中・大の観点}: {理由}。他は小）

**依存先:** 論点K（{依存先がどう決まれば、この論点の案を作れるか}）
```

## 回の骨子

```markdown
### イテレーションI（論点N）: {この回で進める内容}

#### 検討記録（論点N・イテレーションI）

{前回の応答から今回の提案へ至る調査・比較・訂正とその結果を、起きた順序と理由が分かる本文で残す。判断に必要な事実・反証・未確認・限界を含める}
```

## 提案本文

```markdown
#### 提案I（論点N）

{その回の問いを判断できる案}
```

## 空の提案応答欄

```markdown
#### 提案Iへのフィードバック（論点N）
```

## 認識合わせ本文

```markdown
#### 認識合わせI（論点N）

{共有事実と、回答・訂正を求める前提・見方・問い}
```

## 空の認識合わせ回答欄

```markdown
#### 認識合わせIへの回答（論点N）
```

## 受領応答の本文

```markdown
**結果:** {その回の結果が分かる短い表現}

> {user feedback、review等を必要な範囲で原文のまま示す}

{評価・得られた入力・訂正・残る不足の補足}
```

## 仮決定

```markdown
### 仮決定（論点N）

{現在有効な仮の判断}
```

## 再開条件

```markdown
### 再開条件（論点N）

{不足、解消を判断するevent・evidence・action、再開する未決判断}
```

## 決定

```markdown
### 決定（論点N）

{現在有効な最終結論と、その制約・選択理由}
```


## 変更内容

以前の記録で、導出・委託した変更の報告に使った保存形である。新しい記録では使わない。以前の記録を読む時に、この形で読む。

```markdown
### イテレーションI（論点N）: 変更の報告

#### 変更内容I（論点N）

変更前と変更後、原因となった原文と出典、既決事項または委託の根拠、対象と範囲、理由、検証と限界を書く。

#### 検討記録（論点N・イテレーションI）

変更の入力・調査・比較・訂正と、今回の変更へ至った結果・理由・限界を本文へ残す。
```

## 現在の変更

以前の記録で、導出・委託した変更の報告と反映の状態に使った保存形である。新しい記録では使わない。以前の記録を読む時に、この形で読む。

```markdown
### 現在の変更（論点N）

iteration、報告した問いまたは完了reviewと版、対象、報告の有無と出典、対応する実応答と原文への参照、反映状況と検証結果、未解決を書く。
```


### 変更の記入例

架空の例であり、実際の合意・検証ではない。実物には対象path・節、原文と確認可能な証拠の出典を付ける。Git管理外の内部logだけを根拠にしない。

```text
#### 変更内容0（論点N）

判断根拠: 合意からの導出。
合意済みの「分割後の入口を一つにする」に従い、案内文の参照を同名索引へ揃える。
変更前は単一入口、変更後は同名索引。対象は案内文の該当link全て。原文・採番・承認条件は保持する。

#### 検討記録（論点N・イテレーション0）

参照先と更新対象を照合し、何を確認してこの変更になったかを本文へ残す。

### 現在の変更（論点N）

iteration0、報告版1、対象は案内文。未報告・未反映。
次の問いまたは完了reviewの直前に報告し、実際の問いと版をここへ記す。
次の当該応答後に、その出典・適用結果・検証・未完を更新する。
```
