# 考え始め

**主軸: 事象から原因へ降り、提案を検証まで通す**

これは思考の順序であり、出力の見出し構成ではない。何をどう書き表すかは
[形式の優先順位](./core.md#形式の優先順位) に従い、consumer 側の指定があればそちらを使う。
各段階を文章として印字することは求めない。求めるのは、次の四つを実際に通過していることである。

**事象を具体で捉える。**
何が起きたか、何が言われたかを、再現できる出来事として押さえる。
「問題がある」「精度が低い」のような総論のままだと、以降の全段階が空回りする。
「X というときに Y が起き、Z になった」まで具体化する。

**原因を、再発を止められる深さまで降ろす。**
一段で止めない。停止条件は「ここを解消すれば同じ事象が再発しない」と言えること。
「守らなかった」「忘れていた」「注意不足」は事象の言い換えであり、原因ではない。
規則・手順・document が既に存在していたなら、なぜそれが参照されなかったかまで降りる。

**提案は、合意した後に何が変わるかが読み取れる粒度にする。**
方向性や rule の文だけで対象と変更内容が決まらないものは、提案ではない。
原因の分類結果や再発防止の方針は提案の材料であって、提案そのものではない。

**検証は、目下の課題が解けそうかで測る。**
弱点の有無を形式として求めない。特段の弱点がない提案もあり、
形式で求めれば無理に捻り出すだけになる。
見るのは、提案を出す起点になった課題に対して解決が図れそうかである。

- 解決の見込みが低い → 深堀りへ戻る
- 解決できそうでも、さらに深める余地がある → 深める
- 深堀りした結果、深堀り前の提案のほうが良い → 袋小路に入ったか、不要な深堀りだった。深堀り前へ戻る

正しい判断のための問い:
- 「この原因は、解消すれば再発が止まるか？事象の言い換えになっていないか？」
- 「この提案に合意したら、何がどう変わるか読み取れるか？」
- 「この提案で、目下の課題は解けそうか？」
- 「深堀りした結果は、深堀り前より良くなったか？」
