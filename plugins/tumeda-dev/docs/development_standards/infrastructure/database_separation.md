# 開発と本番の DB の分け方

開発の環境で使う DB を、本番の DB と分けるかの判断基準。

## 個人用の service は、本番と開発で DB を共用してよい

個人用の service は、本番と開発で DB を共用してよい。特に、利用者が本当に自分しかいない service は共用する。

理由:

- 分けると、開発のたびに schema とデータを用意する作業が増える。
- 一般の system の前提（本番と開発は分ける）をそのまま当てはめると、利用者が望まない構成が design に入る。

前提が変わる場合: 今は自分だけが使っていても、他の人が使うことになる service、または長く運用して溜まったデータを毀損しない形にしたい service は、他の人が使う system と同じく、分けるかを利用者と検討する。検討した結果、分けないこともある。例えば、開発で app を動かす環境は本番と分けつつ、DB は本番と共有する形がある。

判断の問い: **「この service を使うのは、この先も自分だけか。溜まったデータを毀損しない形にする必要があるか」**

## やってしまいがちな失敗

- 個人用の service の全体構成を設計する時に、「ローカルでも動く形にしたい」という依頼から開発用の DB を本番と分けると推論し、構成の一行として開発用の DB を置く。
    - 分けるかを利用者へ問わなかったため、利用者は合意したつもりが無く、後の作業で design と roadmap を直すことになった。
