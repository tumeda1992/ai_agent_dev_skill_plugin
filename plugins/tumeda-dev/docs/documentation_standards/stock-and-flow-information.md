# ストック情報とフロー情報の扱い

情報を **どれくらい長く残すか（寿命）** で分類し、置き場所と書き方を変えるための方針。

## このファイルの位置づけ

- ある情報を「永続ドキュメントに残すのか／使い捨てるのか」を判断するための考え方
- 上位方針であり、具体的な置き場所の運用（steering・reports など）は各仕組み側が持つ

## 分類

| 種別 | 定義 | 寿命 | 置き場所の例 |
|------|------|------|--------------|
| **ストック情報** | 今後もずっと参照する情報 | 永続 | `docs/` 配下（開発標準・ドメイン docs）、README |
| **フロー情報** | その場で使い捨てる情報 | 一時的 | 調査・検証の作業メモ、scratchpad、`reports/**/for_local` |
| **グラデーションフロー情報** | 使い捨てだが、あるゴール達成までは捨てられない情報 | ゴール達成まで | `.steering/`（案件の計画・進行状況）など |

判断の問い: **ゴール達成後も、文脈を知らない人が参照するか？**
→ する = ストック / しないがゴールまでは要る = グラデーションフロー / その場限り = フロー

## ストック情報

### 満たすべき品質: 無前提で分かること

初見の人が読んでも、事前情報なしで理解できるように書く。前提が要るなら、その前提ごと案内する。

### なぜか

ストック情報は、議論や調査が終わって時間が経った後に、**その文脈を知らない初見の人が読む**。書いた本人の頭にある前提は、読み手の頭には無い。結論だけ転記しても、なぜそうなったか・何が問題だったかが復元できず、使えない資料になる。

### アンチパターン: 議論結果をそのまま転記する

「大事だから」と議論の結論をストックに移す際、**議論の流れを知らないと理解できない内容を、前提なしで貼り付けてしまう**。

直し方:

- 残すものは、**因果関係・それが問題になった具体背景を添えて、初見向けに書き直す**（結論だけ載せない）
- 議論のうち、**残す必要がないものは落とす**（全部を移さない）

## フロー情報

ある調査・議論などの、その場で使い捨てる情報。

### アンチパターン: フローをストックのように当てにする

フロー情報そのものの残し方にアンチパターンは無い（使い捨てなので雑でよい）。問題は、**後からも参照されることを期待して、フローを使い捨ての場所に置いたまま放置する**こと。

直し方: 後から参照する価値があるなら、**ストックの場所へ移す**。その際は上記のストックの品質（無前提で分かる）を満たすよう書き直す。

## グラデーションフロー情報

フロー情報だが息が長く、**あるゴールを達成するまでは捨て置けない**情報（例: 案件の計画・進行状況）。

扱い:

- ゴール達成まで残す。品質は**ゴール達成に必要な範囲**でよく、ストックほどの無前提性は求めない
- ゴール達成後は落とす。ただし、その後も参照する価値があるものだけ、ストックへ昇格させる（昇格時はストックの品質を満たすよう書き直す）
