# 旅行予約のケース — 王道（旅程を組む・人数を変える）

旅行予約でよくある本筋のケース。全体の地図・概要・対象外は [`overview.md`](./overview.md)。キャンセルは [`cancel_cases.md`](./cancel_cases.md)、周辺は [`other_business_cases.md`](./other_business_cases.md)、データ整合性は [`data_integrity.md`](./data_integrity.md)。深い仕組み（決済・返金計算・在庫連携）は各モジュールへ譲る。

## 旅程を組む（予約・発券）

航空券とホテルを予約して旅程を組む。**2 つは独立に、どちらの順でも予約できる**。両方が予約済になれば旅程成立。航空券はさらに発券して座席を確定できる。

```mermaid
flowchart LR
  S["まだ何も予約していない"] -->|航空券かホテルを予約| M["片方だけ予約済<br>（手続き中）"]
  M -->|もう片方も予約| K["両方予約済＝旅程成立"]
  K -->|航空券を発券| T["発券済で成立"]
```

### BK-1. 予約する

航空券・ホテルをそれぞれ予約する（順序は問わない）。片方だけ予約した「手続き中」を経て、両方揃うと旅程成立。

### BK-2. 航空券を発券する

座席を確定する。以降は変更・払戻に手数料などの制約がつく（＝以降の操作は「発券済」扱い）。ホテルが既にキャンセルなら、この発券で「発券済なのに宿無し」に入る（キャンセル章 CX-4 と同じ最厄介状態）。

### BK-3. 宿を取る前に航空券を発券した（発券済・ホテル未予約）

発券済だが宿はこれから。**まだ宿を取れる（回復可能）**。宿を取り消した [`cancel_cases.md`](./cancel_cases.md) の CX-4（発券済 × ホテルキャンセル）とは別——未予約は「これから取る」、キャンセルは「取り消した後」。

片方を予約した後にそれをキャンセルすると、もう片方が未予約のまま半端な状態になる。そのキャンセルの起こり方は [`cancel_cases.md`](./cancel_cases.md)。そこから残りを予約すれば「片方だけ消えた」旅程に入る。

## 人数を変える

旅程の人数を変える。**発券前後**と**各予約の空き・最低人数**で効き方が変わる。状態（航空券×ホテル）は変えず人数と課金を動かす（減員で最低を割るときだけキャンセルへ遷移）。効くのは「予約済（生きている）側」で、旅程がどの局面でも同じ規則:

- **成立後の旅程**（両方生存）: 両方の予約で人数を変える。
- **手続き中**（片方がまだ未予約）: 予約済の側だけ人数を変えられる。もう片方は予約するときに人数を合わせる。
- **片方がキャンセル済**: 生き残った側に効く（通常は旅程の壊れを先に解消する）。

発券前後での効きの違い:

| | 航空券が予約済 | 航空券が発券済 |
| --- | --- | --- |
| 増員 | 空き次第で増員 | 座席追加に制約（手数料）。通らなければ保留 |
| 減員 | 最低超なら減員・返金／最低ちょうどはキャンセルへ | 同上＋発券済の払戻制約 |

### PS-1. 増員・全対象予約に空きあり

各予約で人数を増やせる。差額を課金する（発券済の航空券は座席追加に変更手数料）。

### PS-2. 増員・一部が満席

例: ホテルは増やせるが航空券が満席。一部だけ増やすと全員分の座席が揃わず旅程がちぐはぐになる。全体を保留するか、取れた分の扱いを決めてから確定する。**取れた分だけ課金して不足を放置しない**。

### PS-3. 減員・最低人数を超えている

人数を減らし、差額を返金する。

### PS-4. 減員・最低人数を割る

定員下限・最少催行を割る予約は維持できない → その予約はキャンセルへ**遷移**する（[`cancel_cases.md`](./cancel_cases.md) の壊れ状態に合流）。減員が状態を動かす唯一のケース。
