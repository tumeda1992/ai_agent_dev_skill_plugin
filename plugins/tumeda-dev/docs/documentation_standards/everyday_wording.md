# 普段の言葉で書く

`documentation_standards/` の傘の下の 1 トピック。**書いた表現を、読み手が普段使っている意味のまま読んで、書き手の意図どおりに受け取れるか**を扱う。

## 一般則

読み手の目に出る文は、読み手が普段使っている意味のまま読んで受け取れる表現で書く。受け取れない表現は、その文で言いたいことを普段の言葉で書き直す。英語か日本語かは問わない。

書き手は、その表現に載せた意味を知っているため、自分では読める。読み手はその意味を知らないため、文を読むたびに訳し直す。訳し直しは一度では終わらない。書き手が作ったテンプレートの表現は、それを使って書かれる成果物へ持ち込まれ、成果物を読む人全員が同じ訳し直しを強いられる。

## 見分ける問い

**この表現を知らない読み手が、普段使っている意味のまま読んで、書き手の意図どおりに受け取れるか。**

受け取れるなら、そのまま使う。受け取れないなら、下の「書き直し方」で書き直す。

## 書き直す表現の二つの型

| 型 | 例 |
| --- | --- |
| 耳馴染みがない。普段の会話で聞かない | 英語: precedence、tie-break、closed-world。日本語の造語: 全量保存宣言、理解依存、意味正本 |
| 聞き慣れているが、ここだけの意味を載せている | owner（その内容を書く場所、責任を持つ担い手）、contract（呼び出し方と、結果の保証）、「所有する」（その節に書く、の意味）、正本 |

二つ目の型は見落としやすい。owner も「所有する」も聞き慣れた語なので、「耳馴染みがあるか」だけを問うと残る。読み手は語を知っていても、ここで載せた意味を知らない。

文脈を離れた例: 業務の手順書で「突合する」「洗い替える」と書く。経理の担当者には普段の言葉だが、手順書を初めて読む開発者には耳馴染みがない。「二つの一覧の件数と金額が一致するかを確かめる」「前回の値を消して、今回の値で入れ直す」と、その箇所でしていることを書く。

## 残す表現

- 識別子、path、file 名、code の例（`caller-contracts.md`、`importDocument(url)` 等）
- 決まった形式（MUST／SHOULD／MAY、TBD、TL;DR 等）
- 開発の会話で、普段の意味のまま使う語（file、directory、code、test、API、class、function、module、error、data、Markdown、template、commit、branch 等）

残すかどうかも、見分ける問いで決める。英語だから書き直す、日本語だから残す、とはしない。

## 書き直し方

**一語ずつ訳語を決めて置き換えない。箇所ごとに、その文で言いたいことを普段の言葉で書く。**

同じ表現が、箇所によって違う意味で使われていることが多い。一語に一つの訳語を当てると、訳語になっただけで何を指すかは読めないまま残る。

- 「owner 境界」を「担当境界」にしても、何の境界かは読めない。その箇所で言いたいのが「この節に書くことと、他の節へ送ること」なら、「この節に書くこと・書かないこと」と書く。
- 同じ owner でも、「主 owner となる節へ書く」で言いたいのは「その内容を主に扱う節へ書く」であり、別の書き直しになる。
- 英語をカタカナにするだけ（owner → オーナー）では、意味は伝わらない。

次の二つは揃える。揃えないと、読み手が別のものと読む。

- 一つの文書の中で、同じものを繰り返し指す語。例: 作業の流れを書く文書で、判断と更新を受け持つ人や skill を指す語を「担当」に揃える。
- 複数の文書に繰り返し出る、同じ役割の小見出し。

## 当てはめる範囲

- 読み手の目に出る文: テンプレートの見出し・本文・記入欄、それを使って書かれる成果物、読み手への応答
- 書き手がその表現を成果物へ持ち込む入口: テンプレートの中の記入の手引き。成果物へは写らなくても、書き手がその語をそのまま成果物へ書く

skill の内部だけでやり取りされる指示の文は、内輪で通じればよいため当てはめない。ただし、指示の文の表現が成果物の見出しや応答へそのまま出るなら、その出る箇所には当てはめる。

## やってしまいがちな失敗

- 「識別子は原文を維持する」という決まりを広く読み、owner、contract、gate のような普通の概念語まで英語のまま書く。これらは識別子ではない。
- 英語の語を日本語やカタカナへ置き換えるだけで済ませる。「所有する」「正本」のように、日本語でも解釈が要る表現が残る。
- テンプレートの記入の手引きは成果物へ写らないからと、手引きの表現を見直さない。書き手が手引きの語を成果物へ持ち込む。

それをやると何が起きるか:

- 読み手が文を読むたびに訳し直す。テンプレートの表現は成果物へ持ち込まれるため、負担は成果物を読む人全員へ広がる。
- 書き手ごとに訳し直し方が違い、同じ表現が読み手によって別の意味に読まれる。

判断の問い: 見分ける問いと同じである。「この表現を知らない読み手が、普段使っている意味のまま読んで、書き手の意図どおりに受け取れるか」
