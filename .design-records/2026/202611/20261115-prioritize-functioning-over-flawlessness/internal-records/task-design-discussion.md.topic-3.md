# 内部検討記録: 論点3 — 「既存のものを消す・残す」の分類に「直す」を足すか

**discussion:** [task-design-discussion.md](../task-design-discussion.md)

**論点:** 論点3

## 開始context

- 問題: 引き渡しに添えられた気づき（利用者は未判断）。`questioning_existing.md` は、理由を歴史的経緯と合理的必然性へ分離した結果を「残す・移す・消す」の三つに分ける。必然性があり置き場も正しいが、中身の一部が誤っているものの行き先が無い。起点の失敗の一つ（一部が code と食い違う概念説明の文書を、置くべき場所にあるのに退避しようとした）は、この場面で起きた。
- 決める範囲: この作業で「直す」を足すか（拾うか切り出すか）と、足す場合の文面。
- 開始時の既決条件: 論点1・2 で、到達点の原則を `starting_to_think.md` の補助節として足した。
- 残る不足: 作業の範囲の判定と、文面。

## イテレーション0: 拾うかの判定と文面

入口は design の TBD 2。`work_scope.md` の判定を使う。

<a id="iteration-0-record-1"></a>

### 判断: この作業で拾うか、どう直すか

推奨は、この作業で拾い、三分類を四分類にする案。目的の外の不備だが小さく、今の作業の review・revert・本番適用の単位を崩さない。

#### 判断対象・必須条件・根拠

- 判断対象: `questioning_existing.md` に「直す」を足すか、足すならその文面。
- 必須条件: `work_scope.md` の二段の判定に従うこと。既存の主軸（理由を分離し、必然性だけを残す）を変えないこと。到達点の補助節と矛盾しないこと。
- 根拠: `questioning_existing.md` の該当行（「分離した結果は三つに分かれる…二択で考えると「移す」が見えなくなる」）。git grep で、三分類を書いている箇所はこの一行だけ（`.steering/` を除く）。`think_standards/README.md` の入口の一行は「理由を歴史的経緯と合理的必然性へ分離し、必然性だけを残す」で、分類の数には触れていない。

#### 作業の範囲の判定（`work_scope.md`）

- 一段目: この作業の目的は到達点の原則を思考標準へ足すこと。「直す」を足しても足さなくても、補助節は成り立つ。完成後の姿は変わらないので、目的の外の不備にあたる。
- 二段目: 一行の変更と検査一つで、同じ思考標準・同じ版上げに収まる。単体で revert したい大きさでも、適用を遅らせるものでもない。今の作業の単位を崩さないので、既定どおり拾う。

#### 文面の判断

- 三分類を四分類にする。「必然性があり配置も中身も正しい（残す）」「必然性があり配置も正しいが中身の一部が誤っている（直す）」を分ける。「残す」に中身の修正を含めて読む手もあるが、起点の失敗はまさにその読みが働かず、誤りを含むものを消す方へ倒れた。明示しないと届かない。
- 「二択で考えると「移す」が見えなくなる」を「「移す」と「直す」が見えなくなる」にする。
- 中身の一部の誤りは消す理由ではなく直す理由である、と一文足し、到達点の補助節（`starting_to_think.md`）へ所在を示す。原則の本体は補助節が持ち、ここには複製しない。
- `validate-plugin.mjs` に「（直す）」を含む分類の文の `requireText` を足す。

#### 起点以外の case での確認

| case | 分類 |
| --- | --- |
| 置くべき場所にある設定 file の、古くなった値が一つある | 直す（値を今の正しいものにする） |
| 正本と、そこから生成される成果物の両方に同じ規則がある（既存の失敗例） | 正本へ寄せ、成果物には所在の指示を残す（移す）。既存の判断と変わらない |
| もう呼ばれない機能の README | 消す（必然性がない） |

四分類で、どの case も一つの行き先に落ちた。「直す」を足しても、既存の失敗例の判断（移す）は変わらない。
