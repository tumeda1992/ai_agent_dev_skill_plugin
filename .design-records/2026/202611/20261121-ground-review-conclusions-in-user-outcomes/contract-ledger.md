# 構造・判断の保持と追加

基準はbaseline.jsonの9.1.0。コピー元の個別事案を移す作業ではなく、依頼された十分性の検討方法を具体に補う。

## 構造の対応

| 元の連続範囲 | 分類 | 改訂後の配置・関係 |
| --- | --- | --- |
| exhaustive-review/SKILL.md全体 | KEEP | 同じ入口・モデル・テーマ・固定・探索・適用・障害・返却。順序と本文を保持 |
| review-findings.md全体 | KEEP | 同じ妥当性・集合・再探索・停止。本文を保持 |
| 全件修正仮定の直前の判定 | ADD | 内部指示の「選んだ例が、利用者に必要な違いを見分けられるか」 |
| coverageへ残す根拠の関係 | ADD | 同じ内部指示の停止節。元の記録内容を削らず、成功・判定・比較根拠を結ぶ |
| 最終返却直前の監督 | ADD | 入口の既存返却節。新しい監督者を設けずSolの判断へ接続 |

## 意味の照合

既存本文は一行も削除・置換しない。追加blockを除去すればbaselineの二つの本文とbyte単位で一致することを検査する。
その上で、以下の既存判断が追加した判定によって弱まらないか通読する。

| 判断のまとまり | 保持する意味と確認先 |
| --- | --- |
| テーマと修正許可 | 挙動維持を全テーマに強制しない。レビューと適用を分け、未合意の対象へ手を出さない |
| 固定と根拠 | 対象・版・未追跡の変化を識別し、再現と推測、机上と実測を混ぜない |
| 個票と集合 | 重複統合、誤指摘撤回、修正責務と依存、0件でも集合検討を行う |
| 再探索と停止 | 周回数や新規ID0だけで停止しない。重要な未知は未完、価値のない水増しは止める |
| 適用と公開 | 具体案と合意の範囲だけ適用し、1指摘1commit・検証・履歴・公開許可を守る |
| 障害と再開 | deadlineと正常な再開を保持し、無制限再試行や完了の偽装をしない |
| 追加の探索操作 | 成功を依頼・契約から独立に取り出し、判定が成功するまま残る重要な差を検証する。単純な導出は例外として保持 |
| 追加の監督操作 | 一番広い返却主張へ根拠を照合し、不足する一点を同じ依頼で戻す。主張を狭めて元のテーマを途中終了しない |

追加の根拠はrequest.mdの品質改善の委託。具体の文案は担当が選び、利用者の逐語承認へ置き換えない。
不要な削除・変更・廃止は0。公開pluginに利用先固有の名前・path・指摘ID・commitは入れない。
