# CR-002　案と総額への採用応答があれば、引渡し理由が本人の優先事項からずれても完了できる

| 項目 | 内容 |
| --- | --- |
| 優先度・観点 | P1、承認と引渡しの整合性 |
| 対象・由来 | 判断手順5・10–12行、比較材料8行。指定範囲に既存。[対象の内容ハッシュ](../coverage.md#対象と手法) |
| テーマとの関係 | 本人が対価を払うと決めた仕事を、次の実装担当が優先して保てること |
| 採否・対応・適用枠 | 未判断、未着手、手順の変更が必要 |
| 依存する指摘 | 単独で承認内容との一致を照合できる。比較した機能の真偽は [CR-001](CR-001-compare-reason.md) |

## 問題と根拠

工程3は本人の採否を取り、工程4は候補名・総費用・採用応答の対応を確認する。採用応答が説明した理由を、受け取る理由文が保持しているかは完了条件に入っていない。本人がどの案を承認したかは確認できても、要約の圧縮や解釈の追加で、保つべき仕事がすり替わりうる。

例えば「両案とも三本の最新情報を読める。発生直後の担当班通知はアプリに加わる機能で、台帳は週200、アプリは週600。通知アプリを採用し、本人の選択に従い全件一覧を最優先で保つ」と渡す。機能と費用の比較は正しく、本人は実際にアプリを選んだが、優先事項の帰属は比較材料8行の応答から導けない。本人が対価と結び付けた仕事は巡回待ちを減らすことである。アプリと金額だけの照合では、表示と通知のどちらを先に保つかという手順の目的を損なう。

## 改善案

工程3では、承認された案・費用と、本人が受け入れた差を特定できる形で、提示した理由と応答を結び付ける。工程4では実際に渡る採用理由を読み、その理由から選ばれる優先事項が当の承認内容に合うかを照合する。意味を保つ言い換えや、明瞭な一つの理由に対する「その理由で採用」は利用できる。資料と応答の範囲で転記を訂正できる場合は訂正し、どの条件を本人が選んだか決められない場合だけ本人に戻す。

## 振る舞いへの影響

資料中の本人応答は差額・目的・候補を既に結び付けているため再投票は不要。採用前の引渡し禁止も引き続き機能する。承認済みの候補名と費用を含んでいても、担当者が独自の優先事項を足した文は差し戻す。

## 検証方法・証拠

[机上対照B・C](../coverage.md#理由文を変えた机上照合) を照合した。機能・額・候補を正しく保ったCが現行の条件を通り得る。提案では応答にある「巡回待ちを減らす」との結び付きからBを受理し、Cの優先事項を訂正する。比較主張の事実確認だけでCを救えない。本人の実際の再承認や修正後の工程は未実施。

## 合意・適用記録

採否未判断。適用の合意、対象変更、適用後の検証、コミットはいずれもない。
