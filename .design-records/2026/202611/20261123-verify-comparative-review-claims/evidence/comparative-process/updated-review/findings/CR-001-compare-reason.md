# CR-001　共有台帳でできる仕事もアプリの差額の根拠として受理できる

| 項目 | 内容 |
| --- | --- |
| 優先度・観点 | P1、比較の正確性 |
| 対象・由来 | 判断手順9–12行、比較材料5–9行。指定範囲に既存。[対象の内容ハッシュ](../coverage.md#対象と手法) |
| テーマとの関係 | 追加費用でどんな仕事が変わるかを、決定者と次の実装担当が同じ条件で判断できること |
| 採否・対応・適用枠 | 未判断、未着手、手順の変更が必要 |
| 依存する指摘 | 単独で比較主張を点検できる。本人がその差を選んだかの照合は [CR-002](CR-002-bind-decision.md) |

## 問題と根拠

工程1は資料の有無を確かめ、工程2は既存資料を使って要約するよう求める。要約の中で「採用案だけでできる」とした仕事を、同じ人・範囲・時点で比較案にも試して読む指示がない。工程4は理由の存在を見れば完了できる。リンク先に正しい事実を保存しても、引渡し文に含まれる誤った比較を検出する条件にはなっていない。

実装担当へ「三本すべての最新の不具合と設備番号を読めるのは通知アプリだけなので、共有台帳の週200に追加400を払い、週600の通知アプリを採用する」と渡す。担当者が台帳を開くと同じ三本の最新情報を読める（比較材料6行）。異なるのは、台帳を開く巡回を待つか、発生直後に担当班へ通知が届くかである。誤った文面でも候補・額・採否は揃う。読む仕事に開発を集中させ、差額を払う理由だった通知を後回しにできるため、判断手順の目的に直接影響する。

## 改善案

工程2で、差額の理由に使う一文を、採用案とその仕事を最もよく代替できる案の資料に対して読んでみる。誰が何をすれば同じ結果を得るか、どのタイミングや操作だけが変わるかを確かめ、共通の機能と有料の差を説明する。工程4でも受け取る文中の比較主張を同じ資料に照合し、矛盾した箇所は作成者に戻す。効果の裏付けが未取得なら、分かっている機能と未観測の効果をそのまま伝える。材料から訂正できる共通機能について本人の好みを尋ねる必要はない。

## 振る舞いへの影響

同じ候補・期間・総費用・差額を使える。正確な比較は受理でき、誤った独占性や裏付けのない成果を含む説明は訂正する。本人の承認は現行どおり引渡しの条件になる。

## 検証方法・証拠

[机上対照A・Bと補助例](../coverage.md#理由文を変えた机上照合) の受取条件を判定した。Aは現行条件を満たすが、提案の条件では共有台帳の記述と矛盾する。Bでは両案で読める仕事と通知の差が資料に一致する。巡回間隔30分を「毎回30分の実測短縮」と言い換えた例も提案では訂正対象になる。元の判断手順による新たな人の決定と修正後の実行は未実施。

## 合意・適用記録

採否未判断。適用の合意、対象変更、適用後の検証、コミットはいずれもない。
