# 製造不具合の対応方式を決める手順のレビュー

対象は [判断手順](../inputs/decision-process.md) と [比較材料](../inputs/materials.md)。決定者が追加費用で何を選び、実装担当が何を優先して保つかを、引渡し時の理由文から特定できるかを調べた。

共有台帳でも三本すべての不具合を読める。本人が追加400を払うと述べたのは、発生直後に担当班へ通知して巡回待ちを減らすためである。現行の受取条件には「全件を読めるのはアプリだけ」と書いた理由も適合しうる。差額と機能を正しく記載しても、担当者が表示の方を本人の優先事項として渡す経路もある。次の二点を順に扱う。

1. **P1**　追加費用に結び付けた主張を、有力な比較案の実際の使い方と照合する。[CR-001](findings/CR-001-compare-reason.md)
2. **P1**　実装担当が受け取る理由と優先事項が、決定者の応答に対応することを確かめる。[CR-002](findings/CR-002-bind-decision.md)

二件を適用した場合の効果は文書上の検討である。照合に使った誤った理由・正しい理由の全文、工程別の判定、対象と手法のハッシュは [coverage.md](coverage.md) に記録した。
